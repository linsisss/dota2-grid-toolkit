# Аналитика (админка)

Попросил владелец 19.10.2026: «сейчас она скудная, нужна полноценная аналитика для понимания всего, что есть на сайте». Раздел «Аналитика» в админке заменил «Статистику». Только администраторам (`CATALOG_ADMIN_TELEGRAM_IDS`): модератору и обычному аккаунту сервер отвечает 403. Публичной страницы и статистики для авторов нет, уведомлений и дайджестов в Telegram тоже нет.

Свой счётчик, без IP и без третьих сторон. Яндекс Метрика (уже стояла на проде) только читается через её API. Дни московские (UTC+3).

## Как считаем

**Посетитель** — HMAC случайной метки браузера (`localStorage gridstudio.visitor`). **Сессия** — HMAC случайной метки сессии. Сессия общая для вкладок сайта и заканчивается после 30 минут без признаков жизни. Браузер под управлением программы (`navigator.webdriver`), запросы роботов (`STAT_ROBOT`) и страницы, подгруженные заранее (`document.prerendering`), не считаются. Админка не считается.

**Отправка.** События копятся в очереди и уходят пачками через `navigator.sendBeacon` на `POST /api/catalog/collect` (если он не сработал — `fetch` с `keepalive`). Пачка уходит:
- через 4 секунды после первого события;
- при 25 событиях в очереди;
- с пульсом каждые 30 секунд, пока вкладка видна;
- когда вкладку скрывают или закрывают.

Первая пачка страницы несёт контекст. Сервер берёт его, только если сессия новая:
- сайт, с которого пришли (только хост);
- `utm_*` из адреса;
- страница входа;
- ширина окна корзиной;
- касание, язык сайта и язык браузера (2 буквы);
- страна по часовому поясу;
- версия сайта.

**Вовлечённое время** идёт, только пока вкладка видна и человек что-то делал в последние 2 минуты: клавиша, указатель, прокрутка или касание. Пульс добавляет не больше 60 секунд. Сессии, восстановленные из старого счётчика, времени не имеют и в средние не входят.

**Устройство, система и браузер** сервер определяет по User-Agent. Хранятся только семейства (`uaFamilies`), сама строка не хранится. Страна берётся из `CF-IPCountry`, если перед сайтом Cloudflare. Сейчас gridstudio.me и dev.gridstudio.me открываются напрямую (185.225.191.222), без Cloudflare, поэтому страна определяется по часовому поясу браузера (`zoneCountry`). IP не хранится нигде.

**Новый или вернувшийся.** Новый — у посетителя ещё не было ни одной сессии. Это строка в `an_visitors`, и в неё же попадают все посетители старого счётчика.

**Источник** определяется по порядку: `utm_source`, иначе сайт-реферер, иначе «Прямой заход». Список источников тот же, что в `server/site-stats.mjs` (`SOURCES`).

**Поиск в мастерской.** Текст запроса хранится, только если он короткий (до 32 символов), из букв и цифр, без длинных цифровых последовательностей, @ и адресов: так остаются герой, тег или ник. Иначе хранится только длина (`searchText`).

**Ошибки.** На каждую загрузку страницы уходит до 8 ошибок скриптов (`error`, `unhandledrejection`):
- сообщение до 200 символов;
- файл без хэша сборки и строка;
- короткий хэш места.

Неудачные запросы к API (`catalogAPI`, кроме 401/403) уходят как адрес с `:id` вместо идентификаторов и код ответа (0 — нет связи). Ответы 5xx сервер считает сам. Всё это хранится в `an_errors` по дням и месту.

## Таблицы

Миграции только добавляют таблицы (`CREATE … IF NOT EXISTS`). Старые таблицы не меняются.

| Таблица | Что | Срок |
|---|---|---|
| `an_visitors` | посетитель → первый день, источник, вход, устройство | пока есть сессии (800 дн.) |
| `an_sessions` | сессия: начало, конец, страницы, вовлечённое время, вход/выход, источник, UTM, устройство, система, браузер, экран, языки, страна, новая ли, версия; `backfill=1` — восстановлена из `visits` | 400 дней |
| `an_events` | сырые события: время, имя, сессия, посетитель, аккаунт, страница, свойства JSON, устройство, источник | 90 дней |
| `an_daily` | свёртка по дню, событию, ключу, устройству и источнику: события, сессии, посетители; ключ `*` — событие целиком; `origin=1` — из старого счётчика | 400 дней |
| `an_errors` | ошибки по дню, виду (`js`, `api`, `server`) и месту | 400 дней |
| `an_installs` | отчёты установщиков: пакет, `ok`/`fail`/`removed`, шаг ошибки | 400 дней |
| `an_logins` | окно входа: где открыли (`from`), устройство, как пошли в бота (`link`/`app`/`code`), /start в боте, «Войти» (1) или «Отмена» (−1), вход на сайте, по ссылке «Вернуться на сайт», новый ли аккаунт; ключ — хеш ID попытки | 90 дней |

Свёртка (`rollupDay`) пересчитывает день из сырых событий. Сегодняшний день пересчитывается не чаще раза в минуту, когда админ открывает отчёт, и ещё раз в час по таймеру. Закрытые дни помечаются в `settings` (`analytics.rolled`). Очистка идёт раз в полсуток. Отчёты кэшируются на минуту.

**История.** В первый запуск ставится `analytics.since`, и утро этого дня сразу восстанавливается из старого счётчика. Через 5 секунд в фоне, по дню за шаг, восстанавливается остальное (`backfill`, отмечается `analytics.backfill=1`):
- `visits` → сессии, по одной на посетителя и день;
- `visits` → `an_visitors` и `page.view` в `an_daily`;
- `stat_events` и `stat_event_parts` → события в `an_daily`: `grid-export` → `editor.export/dota`, `customize-pack` → `customize.build-done` с частями, `login`, `studio-save`, `send-pc`, `dotadle-done`.

Сетки, лайки, комментарии, скачивания (`downloads`), мини-игры (`minigame_scores`) и Dotadle (`dotadle_plays`) читаются прямо из своих таблиц. Таблица `installs` хранит команды только 7 дней, а отчёты установщика появились только сейчас.

Старый счётчик продолжает работать: `/collect` пишет и `visits` (для «Сейчас на сайте», «Пользователей» и первых шагов воронок), и `stat_events` для экспорта, сборки, «На ПК» и Dotadle.

**Нагрузка на запись.** Одна пачка — это одна транзакция с подготовленными запросами. Тест «write cost» даёт около 0,08 мс на пачку из 5 событий в памяти. Лимиты `/collect` и `/install/report` держатся в памяти (`burst`), а не в таблице `limits`.

## События

Полный список и типы свойств — в `scripts/analytics-events.mjs`. Тест проверяет, что каждая запись корректна. Свойства бывают:
- `id` — латиница, цифры и `_.:-`;
- `int` — с пределами;
- `enum`;
- `bool`;
- `text` — короткий, очищенный;
- `ids` — список.

У события может быть ключ, по которому идёт свёртка, и `once`: один раз за сессию на ключ.

| Где | События |
|---|---|
| Страницы | `page.view {page}` — `home`, `studio`, `editor`, `customize`, `workshop…`, `work:<id>`, `guide:<id>`, `profile:<key>`, `minigames[:игра]`, `dotadle`, `advertise`, `rules`… |
| Оформление Dota | `customize.scene`, `.section`, `.change` (once на раздел), `.preset`, `.chat-drag`, `.cursor-creator`, `.mod` (мод d2pfx), `.inside`, `.build-start/done/fail` (`parts`, `mb`, `pack`), `.download`, `.command-copy`, `.install-help`; `pc.send` |
| Редактор | `editor.file`, `.tool` (once на инструмент), `.mode`, `.edit` (once), `.ascii`, `.import`, `.export` (`dota`/`command`/`png`/`sketch`/`project`/`optimized`), `.publish`, `.undo-heavy` (25 отмен) |
| Мастерская | `workshop.search`, `.filter`, `.open`, `.download` (`file`/`command`/`editor`/`builder`), `.like`, `.comment`, `.report`, `.install-help`, `.command-copy`; `profile.follow` |
| Гайды | `guides.read {depth 25/50/75/100}`, `guides.write {open/submit}` |
| Мини-игры, Dotadle | `minigames.open/start/finish/submit/ranks`, `dotadle.start/finish/share` |
| Вход, реклама | `auth.login-start {from}`, `.login-done`, `.logout`; `spot.view` (баннер виден наполовину, once), `spot.click {place, target}` |
| Ошибки | `error.js`, `error.api` (хранятся в `an_errors`) |
| Сервер | `auth.login`, `studio.save`, `install.command` (собран пакет или команда сетки), `install.report`, `minigames.run`, `minigames.record`, `dotadle.guess` — со страницы не принимаются |

Готовых артов в мастерской нет: они в библиотеке редактора и считаются как `editor.import {kind: art|library}`. Теги мастерской в `workshop.filter` отправляются латинскими слагами (`anime`, `cute`…).

## Установки: шаг «поставил»

Скрипты PowerShell — сетки, фон, шрифт, «Оформление» одним файлом и все команды «вернуть как было» — в конце шлют `POST /api/catalog/install/report` с `{pack, result: ok|fail|removed, error: шаг}`:
- `pack` — `all-<sha256>`, `bg-…`, `font-…`, `grid-<id>` или `<вид>-remove`;
- `error` — шаг, на котором скрипт остановился: `download`, `find`, `copy`, `remove`, `grid`.

О компьютере, аккаунте Steam и папках не отправляется ничего. Это `Invoke-RestMethod` с таймаутом 5 секунд внутри `try { } catch { }`: любая проблема с отчётом проглатывается и на установку не влияет.

Сервер принимает этот запрос без Origin, потому что PowerShell его не шлёт, но отказывает чужому Origin и `Sec-Fetch-Site: cross-site`. Страница кладёт тот же `pack` в `customize.build-done`, `customize.command-copy` и `workshop.command-copy` (`packOf` по тексту команды). Воронка считает «поставил», когда для пакета этого посетителя есть отчёт `ok` в пределах периода плюс 7 дней.

| Вкладка | Что показывает |
|---|---|
| Обзор | «Сейчас на сайте» и сегодня (`/admin/stats/live` каждые 10 с); плитки с изменением к прошлому периоду; посещаемость (с «Сравнить» — прошлый период серыми линиями); время, регистрации, скачивания, установки по дням; страницы |
| Источники | источники с отказами, временем и изменением; источники по дням; сайты; новые аккаунты по источнику; UTM; страницы входа |
| Аудитория | новые и вернувшиеся; недельные когорты (до 12 недель); тепловая карта день × час; распределение времени; устройства, системы, браузеры, экраны, страны, языки |
| Инструменты | оформление: разделы (открыли → изменили → в сборке), моды d2pfx, готовые варианты, сцены, сборки и ошибки, установки по видам и шагам ошибок; редактор: инструменты (доля сессий), режимы, экспорт, импорт, файлы, ASCII; мастерская: действия, поиск (с пустыми результатами), фильтры; гайды: дочитывание; вход, «На ПК» |
| Воронки | оформление: зашёл → изменил → собрал → скачал или скопировал команду → поставил; редактор: открыл → изменил → экспорт → опубликовал; мастерская: зашёл → открыл работу → скачал или взял команду → поставил. Каждая — по устройствам |
| Контент | публикации, лайки, комментарии, подписки по дням; топ сеток, фонов, гайдов, авторов; мини-игры; Dotadle; промахи поиска Dotadle |
| Ошибки | скрипты, запросы, сервер — по дням и по месту; версия, где ошибку видели в последний раз |
| Метрика | данные Метрики за тот же период или инструкция, если токена нет |
| Реклама | показы, клики и CTR по местам; клики по «Здесь может быть ваша реклама» |

Воронка «Вход» (19.10.2026: из 337 окон за сутки входом кончались 89, остальные не доходили до бота) считается по окнам входа (`an_logins`), а не по посетителям: открыл окно → нажал «Перейти в бота» (или бот получил /start) → бот получил /start → «Войти» в боте → вошёл на сайте. Под ней — вошедшие по «Вернуться на сайт», «нажали «Войти», но сайт не завершил», отмены, новые аккаунты, таблица по месту открытия окна и способы дойти до бота. Фильтр по устройству применяется, по источнику — нет.

«Контент → Повторные скачивания» (`repeats`): по `workshop.download` с посетителем — кто скачивал сетки и фоны, кто в разные дни, кто тот же файл снова в другой день (значит, ставил заново), медиана дней между разами и что скачивают заново чаще.

Воронки считаются по посетителям: дошедший до шага считается и на всех шагах до него (`funnelSteps`). Так история из старого счётчика, где была видна только сборка, не обнуляет шаг «изменил». Воронки строятся по сырым событиям, поэтому период для них обрезается до последних 90 дней.

Фильтр «Источник» на вкладке «Источники» не применяется. На вкладках «Контент», «Ошибки» и «Метрика» нет фильтров по устройству и источнику. История из старого счётчика знает только «телефон» или «компьютер» и не знает источник событий.

Графики рисуются в SVG без библиотек по правилам dataviz:
- категориальные цвета проверены валидатором на фоне `#1b1922`;
- линии 2 px, столбцы до 24 px со скруглением и зазором 2 px;
- сетка — сплошные тонкие линии;
- подсказка с перекрестием на линиях и подсказка у каждого столбца или ячейки;
- у каждого графика есть таблица и CSV (разделитель «;», UTF-8 с BOM).

## Яндекс Метрика

Чтение через Reporting API (`stat/v1/data`): 17 отчётов — сводка, дни, источники, поисковые системы, поисковые фразы, сайты, соцсети, страны, города, возраст, пол, устройства, системы, браузеры, глубина, время, страницы входа. Каждый отчёт запрашивается отдельно: отказ одного не мешает остальным. Ответы кэшируются на час по периоду. Счётчик — `METRIKA_ID` из `scripts/metrika.mjs`. Токен передаётся только в заголовке и в ответах админки не появляется.

Подключение (текст есть и во вкладке):
1. oauth.yandex.ru → «Создать приложение», доступ «Яндекс.Метрика: получение статистики» (`metrika:read`).
2. Войти аккаунтом с доступом к счётчику 113559366 и получить токен: `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ID приложения>`.
3. Записать `METRIKA_TOKEN=<токен>` в `shared/catalog.env` (для dev — `dev/shared/catalog.env`).
4. Перезапустить API.

# Кастомизация Dota 2 (`/background`)

С 1.6.3 сборщик живёт на `/background`; `/customize` (1.6.0–1.6.2) отвечает 301 на `/background` с тем же запросом (`?background=`, `?item=`, `?tab=`), в nginx и в Vite (`scripts/editor-route.mjs`). Файл страницы по-прежнему `customize.html`, внутренний маршрут превью — `/api/catalog/page/customize`.

С 1.6. Страница `customize.html` (`src/customize/`) — два отдельных инструмента без вкладок: сборщик фона меню (`/customize`) и шрифт (`/background?tab=font`; с 02.10.2026 на dev ссылки «Шрифты» на главной и в боковом меню «Студии» активны по решению пользователя — до этого были «скоро»; пак ещё не проверен в игре). Готовые фоны — в мастерской, раздел «Фоны» (старая ссылка `?tab=gallery` ведёт туда). Каждый — один экран без прокрутки: превью слева, настройки в панели справа, установка — в окне (открывается само после каждого скачивания: с командой или шагами вручную). Уже 900 px — обычная страница с прокруткой. Панель сборщика фона помещается без прокрутки от 768 px высоты окна (проверено на 768, 800, 860, 950 и 1080 во всех состояниях, с 1.6.4): короткие пояснения стоят в строке названия поля справа (`Field aside`: экран, «Заполнить/Целиком»), размытие, затемнение и масштаб — один ряд, подсказка про формат файла видна, пока файл не выбран, галочки — плотным блоком с подписью в одну строку, «Папка в Dota» — одной строкой (предупреждение только у `dota_123`, про `pak01_dir.vpk` сказано в «Как установить»). Ниже 1040 px заголовок панели остаётся только для читалок экрана, ниже 860 px у галочек остаются одни названия. Сайт выдаёт готовые файлы, пользователь кладёт их в папку Dota. Ничего не проверено Valve; изменение файлов игры формально не разрешено правилами Steam, банов за шрифты и фоны меню не известно — это сказано на странице.

## Одна страница «Твоя Dota» (17.10.2026, dev)

Запрос владельца: «чтобы и фон собирался на этой странице и всё вообще на ней происходило, сборка 1 общего файла. Весь интерфейс (то есть всё кроме сеток и гайдов) будет в одной странице». Выбран макет «A · Сцена» (`/mockups/customize/a.html` на dev), в подвал — список из макета C. Адрес тот же — `/background` (nginx не менялся).

- `src/customize/CustomizePage.jsx`: сверху переключатель сцен с живыми миниатюрами (Главное меню / Сетка героев / За героем / Загрузка / Матч; точка — в сцене есть изменения), «16:9» листает пропорции экрана фона, «Изменено N из 10». Большое превью — сцена. Справа аккордеон по группам: «Главное меню» (Фон меню, Под сеткой героев, За героем, Экран загрузки, Кнопки меню), «Матч» (Вид HUD, Чат, Курсор), «Везде» (Шрифт, Тексты). У раздела метка «Своё» / «Как в меню» / «Как в Dota» и «Сбросить»; открытый раздел переключает превью на свою сцену («Шрифт» — сцена шрифта вне переключателя). Подвал «Одним файлом»: число изменений и размер, иконки разделов, строка «что в сборке», «Командой PowerShell / Только файл», кнопка, «Что внутри» (каждая часть с размером и полоской доли, потом файлы архива), «Как установить». На телефоне превью липнет сверху, внизу полоса «Прислать на ПК».
- Состояние каждого раздела живёт в своём хуке: `useMenuBackground` (MenuBackground.jsx — фон, страницы, кнопки, пак pak02), `useInterface` (InterfaceBuilder.jsx — HUD, чат, курсор, тексты; localStorage `gridstudio.interface`, как было), `useFont` (FontPicker.jsx; теперь по умолчанию «Шрифт Dota», выбор запоминается в `gridstudio.font`). Логика сборки прежняя: те же `packBackground`, `interfacePack`, `cursorFiles`, `dotaFontPack` — на одинаковых настройках pak02 и pak03 побайтно совпадают с выдачей старых инструментов (проверено 17.10.2026).
- «Как в Dota» значит «в файл не попадает». Без фона меню pak02 собирается только из остального (`menuBackgroundPack({ video: null })`: dashboard пишется лишь чтобы скрыть кнопки; «Как в меню» за героем и на загрузке тогда равно «Как в Dota»). Кнопки Stratz и Dotabuff в профилях теперь выключены по умолчанию (включённые — изменение Dota). Размеры до сборки: всё, кроме видео, собирается сразу (pak03, курсор, шрифт — через 0,3 с после изменения), видео — по цели кодировщика со знаком «≈», после сборки — настоящие.
- Один файл — `gridstudio-dota.zip` (`scripts/customize-pack.mjs`): `game/dota_russian/pak02_dir.vpk`, `game/dota_russian/pak03_dir.vpk`, `game/dota_russian/resource/cursor/…`, `game/dota/panorama/fonts/<файлы Valve>.otf`, `OFL.txt`, `ПРОЧТИ.txt` — вручную папка `game` копируется в `dota 2 beta` с заменой. Команда: пакет `all` в `server/install-packs.mjs` (до 120 МБ; принимаются только эти имена, pak02 — как фон, но можно без видео меню, pak03 — только `custom_ui.vcss_c` и файлы локализации, курсоры — BMP Valve по id и размеру), скрипт `customizeScript` (`/api/catalog/install/all-<sha256>-<size>`): кладёт файлы dota_russian (заменённое — рядом `.gridstudio-backup`, как у фона), шрифты поверх Valve (оригиналы — в `gridstudio-backup`), пишет список в `dota_russian/gridstudio-installed.txt`; следующая установка убирает файлы прошлой, которых нет в новой сборке, и возвращает шрифты Valve, которые больше не заменяются. `all-remove` возвращает всё и язык озвучки. Проверено в pwsh 7 на копии папки (установка → большая сборка → маленькая → удаление).
- Старые адреса: `?tab=font` → «Шрифт», `?tab=interface` → «Матч / Вид HUD», `?page=grid|hero|loading` → свой раздел, `?part=<раздел>` — новый вид адреса (страница его ставит сама), `?background=<id>` и `?item=<id>` — «Фон меню» с этим фоном, `?tab=gallery` — мастерская.
- Статистика: одно событие `customize-pack` с частями сборки (`stat_event_parts`).

## Фон главного меню

Как это устроено в игре (сентябрь 2026):

- Фон выбирает `DOTADashboardBackgroundManager` в `panorama/layout/dashboard.xml` по атрибуту `override-background` (Valve сама ставит туда путь к сезонной разметке, например `…seasonal_reward_line_fall_2026.vxml_c`). Настройки в игре нет.
- Dota подключает все `pak*_dir.vpk` из `game/dota_<язык озвучки>/` раньше основных файлов — только у настоящего языка. `dota_english` не читается никогда (английский — базовый язык, его папку игра не подключает; Dota 2 Mod Manager проверял дважды в августе 2026), выдуманные языки (`-language 123`, `dota_123` из старых гайдов) — с обновления 23.07.2026 (Minify, Dota 2 Mod Manager). Пропуски в номерах не мешают: `pak02_dir.vpk` подключается и без `pak01_dir.vpk`.
- Поэтому файл всегда кладётся в `game/dota_russian/pak02_dir.vpk` (рядом `pak01_dir.vpk` — русская озвучка, если она скачана), а языком озвучки должен быть русский. Он хранится в `game/dota/cfg/boot.vcfg` (`"boot" { "UILanguage" "…" "AudioLanguage" "…" }`, Dota читает файл при запуске и пишет при выходе) или ставится в настройках Dota; параметр запуска `-language` важнее файла. С 1.7 в сборщике вместо «Папки в Dota» — «Язык Dota»: «Русский» и «English» дают один и тот же файл, отличаются только шаги установки. У английской Dota интерфейс остаётся английским, а герои говорят по-английски, пока русский пакет озвучки не скачан (Steam его сам не качает). Рецепты «Студии» со старым `folder: 'custom'` читаются как `russian`.
- Видео внутри VPK указывается как `s2r://…webm` в `<MoviePanel>`; нужен WebM VP8/VP9 без Opus-звука (в libavcodec Dota нет декодера Opus). Слишком большие файлы дают чёрное меню, поэтому цель — до ~15 МБ.

Что собирает сайт (`scripts/menu-background.mjs`, `server/menu-backgrounds.mjs`):

| `panorama/layout/gridstudio_background.vxml_c` + `panorama/styles/gridstudio_background.vcss_c` | `<MoviePanel>` на весь экран, чёрная подложка |

### Качество видео (проверено 01.10.2026)

Проверка: тестовые ролики (детальный арт с наездом 4K 60 к/с, фрактал 1080p 60, гладкий и шумный тёмные градиенты, арт с плёночным зерном 30 с; MP4 H.264 с пометкой BT.709, как обычные скачанные) прогнаны через сборщик на dev в Chrome, видео достано из пака и сравнено с идеальным 1080p 30 к/с 4:2:0 (FFV1, тот же кадр) по PSNR и SSIM (ffmpeg), плюс кадры в 2×.

- Что меняется намеренно: 4K → 1920 × 1080 (на мониторах 1440p и 4K Dota растянет), 60 → 30 к/с, ~4 Мбит/с (30 с — 3,2): Dota показывает чёрное меню на больших видео. Цвет переводится в BT.601 (limited) с пометкой в WebM; средний цвет отличается меньше чем на уровень из 255.
- Сам кодировщик браузера (VP9 через WebCodecs, libvpx) не хуже ffmpeg: двухпроходный libvpx-vp9 при том же размере дал то же (арт 31,4 против 31,6 дБ RGB, фрактал чуть лучше у ffmpeg, гладкий градиент — у браузера).
- Потери сжатия: детальный арт — SSIM 0,993, PSNR(Y) 42 дБ (на глаз не отличить), гладкий градиент — 0,999 / 43 дБ, зерно 30 с — 0,988 / 41 дБ (мелкое зерно сглаживается), фрактал — 0,96 / 32 дБ (предельный случай).
- Было до 1.6.4: опорный кадр каждые 2 с (так у Mediabunny по умолчанию). Фону, который только крутится по кругу, перемотка не нужна; с опорным кадром раз в 10 с (`KEY_FRAMES`) при той же цели файлы меньше, а шумные заметно чётче: шумный градиент 10 с — 13,9 → 10,4 МБ и 32,6 → 36,8 дБ, зерно 30 с — 14,2 → 12,6 МБ, арт — то же качество. Один опорный кадр на весь ролик почти ничего не добавляет.
- Было до 1.6.4: на шуме и зерне VBR не держит цель (шумный 30-секундный ролик — 22,7 МБ при цели 12), такой фон в Dota мог дать чёрное меню. Теперь `fitSize` в `menu-video.js` собирает видео больше `MENU_LIMITS.maxVideoBytes` (14 МБ) ещё раз: на таких роликах размер падает примерно как кубический корень битрейта (3,2 / 1 / 0,5 Мбит/с → 22,7 / 16,5 / 12,7 МБ), поэтому битрейт снижается в куб превышения (тот ролик — 12,3 МБ со второго раза, 33 дБ). Третья попытка — постоянный битрейт (CBR): влезает всегда, но шум мылит сильнее (32,2 дБ); сразу CBR не подходит — на шумном градиенте он давал 25 дБ.
- Кодировщик берётся программный (`hardwareAcceleration: 'prefer-software'`), если браузер его даёт, иначе любой: аппаратные VP9 (Intel) при таком битрейте обычно хуже, и результат зависел бы от видеокарты. На сервере ролик 30 с собирается за 10–13 с.

### Ивент (с 1.6.4)

Фон меню Valve по умолчанию — это сам сезонный ивент (сейчас «Диковинки Квортеро», `dashboard_background_seasonal_reward_line_fall_2026`: награды, разряды, таймер, кнопки «забрать»). Наш `override-background` его прячет, поэтому пак оставляет ивент в одном клике:

- Кнопка на главной, под карточкой события в колонке новостей (`margin-top: 600px` — на 16 px ниже карточки, как Valve расставляет свои ячейки; справа 58 px, 330 × 56), а без новостей (выключено «Отображать новости на главной») — на месте колонки (`100px`). Видна только на главной (класс `.OnHomePage` от Valve). Выглядит как ячейки Valve в этой колонке (`frontpage_shared.css`, `front_page_dark_carnival.css`), чтобы не спорить с меню: тёмная подложка цвета теней карточки Dark Carnival (`#0d0f18`), едва видная рамка, логотип ивента 40 px чуть приглушён, заголовок как у ячеек — Radiance 16 px, заглавными, серый `#cccccc` с чёрной тенью; при наведении рамка, подложка и текст светлеют. Первый вариант (золотая рамка, жёлтый жирный заголовок 20 px, 76 px высотой) работал, но слишком выделялся. По клику фон меняется на ивент, а надпись — на «НАЗАД»; второй клик возвращает фон. Анимации как в превью сборщика: кнопка въезжает справа вместе с главной, ивент проявляется поверх видео, оседая из лёгкого увеличения (0,6 с; видео сворачивается, когда его уже закрыло), и гаснет за 0,25 с, надпись и «НАЗАД» меняются, уезжая вверх и приходя снизу. Приём Valve для панелей, которые сворачиваются (`popup_dark_carnival_encounter_slark_jailbreak.css`): `opacity` и `transform` с `visibility` в `transition-property` — панель сворачивается, только когда исчезла. После перезапуска Dota снова показывает фон.
- Как устроено: `<Button onactivate="ToggleStyle( DashboardCore, GridStudioShowEvent )">` вставляется в `dashboard.xml` Valve сразу после `#DashboardPages`, рядом подключается стиль `gridstudio_menu.vcss_c`. Наша разметка фона держит разметку ивента (текущий `override-background` Valve) в `<CustomLayoutPanel id="GridStudioEvent">`, свёрнутой; CSS по классу на `#DashboardCore` показывает ивент и прячет видео.
- Правила Dota, найденные тестами в игре 01.10.2026 (в retail-клиенте ошибка одна — «Unable to load layout file… File might be corrupt», после неё клиент закрывается и Steam проверяет файлы): разметка по новому пути с обработчиком событий (`on…="…"`) не загружается, и это фатально — в том числе внутри `CustomLayoutPanel`. Файлы Valve, которые мы подменяем (`dashboard.xml` с 42 обработчиками, страница героя), работают с обработчиками. Поэтому кнопка — в `dashboard.xml`, а наши разметки без обработчиков. Ни в одной разметке или стиле Valve нет не-ASCII символов, и наши тоже только ASCII: тексты — токены локализации Dota (`#DOTA_Seasonal_Quartero_Title` → «Диковинки Квортеро» из `quartero_russian.txt`, в одну строку; `#DOTA_Reward_Line_Fall_2025_Title` — тот же текст с `<br>`, в первой проверке он давал две строки; `#UI_BACK` → «НАЗАД»). Кириллица в разметке не проверялась. `menuBackgroundPack` проверяет оба правила на каждом файле и не соберёт пак, который их нарушает.
- Какой ивент — `assets/dota-menu/event.json`: название для сайта, разметка (`override-background` на момент записи), токен заголовка и логотип (`panorama/images/events/seasonal/artwork/…`). Кнопка собирается, только если разметка совпадает с `override-background` нашего `dashboard.xml` (`menuEvent`). Когда Valve переходит к следующему ивенту, `check-dota-menu.mjs` отвечает `override-only`; после `--update` кнопки в паках нет, пока `event.json` не описывает новый ивент: разметку взять из `dashboard.xml`, токен и логотип — из разметки ивента и `resource/localization/dota_*.txt` в декомпилированном клиенте, проверить пак в игре и вырезать новые картинки для превью.
- Превью (`DotaMenu.jsx`, проп `event`): кнопка нарисована в CSS по тем же числам, что и в паке; логотип вырезан со скриншота меню с паком (отделён от тёмной подложки кнопки), надписи «Диковинки Квортеро» и «Назад» нарисованы шрифтом Radiance, как панель друзей (`scripts/make-menu-event.mjs`, скриншоты пользователя от 01.10.2026 в репозиторий не попадают). Всё анимировано (`customize.css`, `.dm-event*`; при «уменьшении движения» анимаций нет): галочка уводит кнопку вправо и возвращает её, логотип и надпись догоняют; при выключении новостей карточка уходит первой, а кнопка с задержкой поднимается на её место, при возврате — наоборот; надпись и «НАЗАД» меняются, уезжая вверх и приходя снизу; экран ивента проявляется, оседая из лёгкого увеличения (только когда картинка загрузилась), и гаснет быстрее. Клик показывает середину экрана ивента между панелью друзей и колонкой (1134 × 959 px, грузится при первом наведении), по краям — та же картинка, размытая. Галочка «Кнопка «Диковинки Квортеро»» есть, только пока `event.json` совпадает с меню.
- Рецепт студии хранит `event`; у рецептов до 1.6.4 его нет — кнопка включена.

Последний шаг — `scripts/compress-hero-3d.mjs` (можно запустить и отдельно, повторный запуск ничего не меняет): лишние ключи анимаций убираются, модели пакуются в `EXT_meshopt_compression` с фильтрами meshopt — повороты 16 бит, смещения и масштабы 12 бит мантиссы, нормали и касательные 8-битные октаэдрические, UV 12 бит, веса костей 8 бит; страница распаковывает их декодером из three (`setMeshoptDecoder`). Координаты вершин остаются точными float: при квантовании их обратное преобразование ушло бы в обратные матрицы привязки костей, а по ним `scene.js` (`skin()`) сажает на кости снимки частиц. На проде с 1.6.3 nginx отдаёт хешированные `webp`, `png`, `svg`, `glb`, `mp3` как неизменяемые (`max-age=31536000, immutable`), раньше — `expires 1d`. Частицы в режиме Mod2x (свечение клинков Arms of Desolation, `particle_modulate_07`) смешивают только цвет (2 × источник × холст) и не трогают альфу холста — иначе квадрат спрайта прорезал в герое прозрачную дыру, заметную на светлом фоне; их текстуры и цвета читаются как есть, без перевода из sRGB, чтобы серый 50 % оставался нейтральным (`fx.js` `texture()`, `QuadBatch`).

В `hero3d/scene.js` на Phong (он даёт только текстуру цвета, нормали, скиннинг и альфа-тест): альбедо = цвет + деталь × маска × blend (огонь `F_DETAIL 2`, сдвиг из `.vmat`: `frac(float2(.197,.035)*time())`); рассеянный = полу-Ламберт основного света × тень + направленный амбиент + цвет в тени; блик = N·L × (L·R)^(маска × экспонента) × свет × scale × маска блика × mix(цвет, цвет блика материала, маска «tint») × max(френель B, металл); металл убирает рассеянный; контур = маска × цвет контура × цвет амбиента × max(N·вверх, 0) × френель R; самосвечение — mix к альбедо. Кривая френеля — `default_fresnelwarprim` игры.
  - Свет и камера — из `portraits_full_body_loadout.txt` (запись `npc_dota_hero_nevermore`): углы, цвет и сила основного света (с тенями three.js), направленный амбиент, цвет в тени; камера игры стоит справа-спереди, а страница поворачивает героя к ней — свет повёрнут на тот же угол. Кадр — по скриншоту игры (камера на 3,48 м с 16,1 м, 30° по вертикали; на экранах уже 16:9 держится ширина). Сцена рисуется в HDR (half float) и сводится мягким коленом по каналам.
  - Эффекты — `hero3d/fx.js`: перенос симуляции частиц Source 2 Viewer (эмиттеры, инициализаторы, операторы, спрайты, шлейфы, ленты, атласы кадров с обрезкой, линейный цвет с overbright, правило «первый пишущий» для систем версии < 6) и свои реализации того, чего там нет: снимки на костях (`InitSkinnedPositionFromCPSnapshot`, `SnapshotSkinToBones`), жёсткие снимки в пространстве точки крепления, `SetPerChildControlPoint` с ориентацией точки, к которой частицы привязаны с поворотом (огонь над головой идёт вверх и назад), иначе по нормали, `LockToBone`, `CreateOnModel` (по костям). Симуляция идёт в пространстве игры (дюймы, Z вверх); контрольные точки — точки крепления моделей по `m_controlPointConfigurations`. Отложенный свет (`RenderDeferredLight`) и искажение (`m_bRefract`) не рисуются.
- **Рецепт.** В рецепте студии (`scripts/studio-background.mjs`) режим хранится в `hero`: `{ mode: 'menu' | 'own' | 'off' }`, у `own` — ещё настройки и источник. У рецептов до 1.6.1 `hero` нет, для них действует «Как в меню».

## Фоны в студии

С 1.6 каждый собранный фон сохраняется в «Студии» (`/editor`, фильтр «Все / Сетки / Фоны», `?show=backgrounds`). Хранилище гибридное, чтобы не держать видео на сервере:

- В браузере (IndexedDB `gridstudio-backgrounds`, `scripts/background-library.mjs`): название, рецепт, JPEG-обложка 480 px и готовый WebM (10–14 МБ), а при своём фоне за героем или под сеткой — и их WebM (`heroVideo`, `gridVideo`). Пак не хранится: «Скачать» в студии упаковывает WebM заново за доли секунды (`src/customize/background-pack.js`, общий со сборщиком) — с той папкой и способом, что были при последнем скачивании. Браузер просим не чистить это хранилище (`navigator.storage.persist`).
- Рецепт (`scripts/studio-background.mjs`): экран, «Заполнить/Целиком», размытие, затемнение, кадр (у рецептов до 1.6.1 его нет — середина, без увеличения), новости на главной (`clean` — скрыты), кнопка ивента (`event`, с 1.6.4; у старых рецептов — включена), кнопки профиля (`profile`, так же), фон под сеткой героев (`grid`, с 1.6.4; у старых — «Как в меню»), папка, способ скачивания, отрезок, склейка и источник — фон мастерской (id) или свой файл (имя, размер, тип). Исходник не хранится нигде.
- Для входа через Telegram на сервер уходят только рецепт и обложка до 60 КБ (`server/studio-backgrounds.mjs`, таблица `studio_backgrounds`, до 200 фонов на аккаунт; `GET /api/catalog/studio/backgrounds`, `PUT`/`DELETE …/:id`, `GET …/:id/poster.jpg` — только владельцу). Видео на сервер не попадает.
- Студия при открытии сводит браузер и аккаунт (`Workspaces.jsx`): несинхронизированные фоны выгружаются (гостевые переходят к вошедшему аккаунту), синхронизированные и пропавшие с сервера удаляются (их удалили на другом устройстве), более новый рецепт с сервера заменяет здешний, а если изменились настройки — старое видео сбрасывается. Фоны аккаунта без видео в этом браузере показываются с пометкой «в аккаунте».
- Карточка открывает сборщик по `/background?item=<id>`: настройки возвращаются сразу, отрезок и склейка — когда станет известна длина видео. Фон из мастерской скачивается сам; для своего файла сборщик просит выбрать его снова (и предупреждает, если имя или размер не совпали). Следующая сборка обновляет тот же фон в студии; новый файл начинает новый фон.

- Статус публикации на карточке: «Опубликовать в мастерскую» возвращает номер заявки и токен (`CatalogBackgrounds.token`, HMAC от номера, ничего не хранится); студия запоминает их (`published` в браузере и в `studio_backgrounds.published` для аккаунта) и спрашивает `GET /api/catalog/backgrounds/:id/status?token=` — «На проверке», «В мастерской» (ссылка), «Отклонён: причина», «Скрыт модератором». Вход не нужен.
- «Мой фон» за сетками (`src/my-background.js`): последний собранный здесь фон — кадр на секунде видео (без видео — обложка) кладётся на экран 1080p, как Dota кладёт фон меню, из него вырезается область сетки героев (`scripts/make-grid-background.mjs`: x 269, y 174, 1,1497 px экрана на пиксель сетки) и затемняется на 45 %, как затемняет игра. Третья кнопка переключателя фона превью в мастерской («Как в Dota / Градиент / Мой фон»; без собранного фона неактивна) и третье значение кнопки фона в превью редактора (`--my-grid-background`). ## Фоны в мастерской

- Теги как у сеток (`BACKGROUND_TAGS`: «Аниме», «Dota 2», «Игры», «Милота», «Мемы», «Dead inside», «Природа», «Космос», «Абстракция»): до трёх, можно без тегов; на карточке — справа под фоном, слева экран и длительность. Хранятся JSON-массивом в `backgrounds.tags`; базы с прежней колонкой `category` переводятся при запуске (категория становится единственным тегом, «Другое» — без тегов).
- Те же фоны — в мастерской: переключатель «Сетки / Фоны» рядом с заголовком (`/workshop?backgrounds`), поиск по названию и автору и теги, как у сеток, «Использовать» ведёт в сборщик по ссылке `/customize?background=<id>` (страница берёт название и экран из `GET /api/catalog/backgrounds/:id`, скачивает видео с прогрессом и убирает параметр из адреса). Карточки и загрузка списка общие — `src/catalog/BackgroundGallery.jsx`, без кодировщика сборщика.
- В «Студии» (`/editor`) кнопка «Создать» предлагает сетку героев или фон главного меню (ведёт сюда); в боковой панели студии — «Фон меню», «Шрифт» и «Мастерская» (шапка студии — только вход), в шапке мастерской — «Шрифт». В сборщике над пустым превью первая ссылка «Где взять» — «Готовые в мастерской».
- Лайки (вход через Telegram, таблица `background_likes`, `PUT /api/catalog/backgrounds/:id/like`) и вкладка «Популярные» (`sort=popular`), как у сеток. Свой фон (`backgrounds.account` — аккаунт вошедшего) лайкнуть нельзя: 403 «Свою работу лайкнуть нельзя.», снять лайк можно всегда. Ответы списка и `GET …/:id` несут `mine` для этого пользователя (не кешируются), и кнопка лайка на своём фоне неактивна, со счётчиком и подсказкой. Лайки авторов на свои фоны, поставленные раньше, удаляются при запуске (`CatalogBackgrounds`, строка аудита `bg:*` / `likes:self-removed:N`, см. [accounts-workspaces.md](accounts-workspaces.md)); гостевые фоны без аккаунта не затрагиваются. Флажок на карточке — «Пожаловаться на фон»: причина и ALTCHA (`report`), по одной открытой жалобе с браузера (`background_reports`, `POST …/:id/report`). Жалобы приходят карточкой «Жалоба на фон меню» в Telegram-топик («Оставить фон» / «Скрыть фон», `kind='background-report'`) и во вкладку «Жалобы» админки фонов («Жалобы проверены» или «Скрыть из мастерской»); счётчик «Фоны» в админке учитывает и заявки, и фоны с жалобами.
- Карточки: видео грузится только при наведении. «Использовать» в мастерской открывает сборщик с этим фоном и тем же экраном; дальше как со своим файлом (отрезок, склейка, эффекты, скачивание).
- «Опубликовать в мастерскую» — внизу панели, на месте подписи под кнопкой сборки; если фон ещё не собран, кнопка сначала собирает его (без скачивания и инструкции), потом открывает окно публикации: название (до 60), автор (до 40), категория (`BACKGROUND_CATEGORIES`), ALTCHA с действием `background`, согласие с правилами мастерской. Уходит ровно то WebM, что внутри пака, и кадр-обложка (JPEG 640 px), одним запросом `POST /api/catalog/backgrounds` (`packBackgroundUpload`: длина и JSON, длина и обложка, видео).
- Картинки в мастерскую не публикуются (16.10.2026, запрос «запретить публиковать картинки для фонов»): в сборщике у PNG, JPEG и статичного WebP (`mediaKind(…).still`; GIF и WebP с флагом анимации в VP8X — нет) вместо «Опубликовать в мастерскую» надпись «Картинки в мастерскую не публикуются», собрать и поставить себе такой фон можно. Сервер проверяет само видео (`stillVideo`): каждые 0,25 с кадр 640 × 360 RGB сравнивается с первым; если ни в одном кадре больше 0,01 % пикселей (23) не отличается сильнее чем на 8 уровней — это картинка, 415 «Картинки в мастерскую не публикуем…». Порог подобран 16.10.2026 на всей галерее (739 видео): у картинок шум кодека 2–4 уровня, у живых фонов (дождь, волосы на ветру, маленький спрайт) — сотни пикселей; все 148 найденных — ровно 10 с, то есть собраны из картинки. Уже опубликованные не тронуты. ffmpeg упал — не отказ.
- Сервер (`server/catalog-backgrounds.mjs`): до 16 МБ видео, ffprobe (`-f matroska`, только файл) должен найти один поток VP8/VP9 ровно размера `MENU_SIZES[aspect]`, без звука, до 30 с (если длительности нет в заголовке — по последнему кадру); обложка перерисовывается, метаданные не сохраняются. Дубли по SHA-256 видео, пауза приёма и блокировки общие с мастерской, лимиты: 3 фона в сутки без входа, 10 с Telegram, 20 на сеть, очередь до 300, всего до 10 ГБ. Файлы — `<id>.webm` и `<id>.jpg` в `CATALOG_MEDIA` (по умолчанию `backgrounds/` рядом с базой), таблица `backgrounds` (pending → approved / rejected, approved ⇄ hidden).
- Отдача: `GET /api/catalog/backgrounds?tag&aspect&q&page` (`aspect` — экран из `MENU_SIZES`; в ответе `aspects` — сколько фонов у каждого экрана при тех же поиске и теге, для фильтра «Экран» в мастерской: `BackgroundScreenFilter`, свой экран устройства — `deviceScreen` в `scripts/background-document.mjs`, отмечен точкой), `GET /api/catalog/backgrounds/:id` (один одобренный фон), `GET /api/catalog/backgrounds/:id/poster.jpg` и `/video.webm` (Range для перемотки; одобренные — `immutable` на год, остальные — только админам, без кэша).
- Модерация: карточка `kind='background'` в Telegram-топике (обложка, экран, длительность, теги; «Одобрить» / «Отклонить» и ссылка «Посмотреть видео» в админку) и вкладка «Фоны» в админке (`/workshop?moderate=backgrounds`: видео, одобрение, отказ с причиной, скрытие, возврат, правка названия/автора/категории). Решения с сайта видны на карточке.
- nginx: `location = /api/catalog/backgrounds { client_max_body_size 18m; … }` (на dev есть; для production — при выкладке 1.6).

## Шрифт

- Панорама рисует текст через fontconfig 2.11 + FreeType 2.5 из обычных файлов `game/dota/panorama/fonts/`. Семейства: Radiance — почти весь текст (чат, подсказки, названия категорий сетки: `#HeroCategoryName`, semi-bold 16px, uppercase, letter-spacing 2px, #808fa6), Reaver — заголовки и верхнее меню, RadianceM — цифры. Только статичные TTF/OTF: вариативные шрифты и WOFF эта версия не понимает.
- Пакет (`scripts/dota-font.mjs`): выбранный шрифт записывается под каждым из 29 имён файлов Valve (`radiance-*.otf`, `radiancem-*.otf`, `reaver-*.otf`) с теми же именами внутри (name ID 1/2/4/6/16/17), весом (`usWeightClass`), флагами стиля, `fsType=0`. На каждое место — ближайшее начертание по весу. fontconfig выбирает эти файлы на тех же запросах, что и оригиналы (проверено `fc-match` на 16 запросах). Пользователь копирует файлы с заменой; откат — проверка целостности файлов в Steam.
- Каталог (с 02.10.2026, по выбору пользователя вместо 16 шрифтов Google Fonts): Audex, Correction Tape, Divagon (GGBotNet), Monocraft (5 начертаний) Cormorant Unicase (4 начертания, Google Fonts — вместо Mason Chronicles, который пользователь просил добавить: Emigre, платный), а из присланных со страниц Google Fonts — Libre Franklin, Oswald, Playfair Display, Comic Relief (вместо Anime Ace: Blambot, только для личного использования) и Bebas Neue (версия Fontfabric 2014 из репозитория Dharma Type: у копии на Google Fonts нет кириллицы); без кириллицы и потому не вошли Smooch Sans, Lobster Two, Original Surfer (параметр `?subset=cyrillic` в ссылке на страницу шрифта ничего не значит — смотреть подмножества в METADATA.pb google/fonts) — `data/dota-fonts.json`, файлы `assets/dota-fonts/<id>/` с `OFL.txt` автора. Пользователь прислал сборку модов Dota (8 шрифтов, переименованных в Radiance/Reaver, рядом оригиналы Valve и `.bat`); из неё взяты только шрифты под SIL OFL, причём из релизов авторов (dafont, itch.io, GitHub): в модах те же файлы с переписанными именами, а у GGBotNet имена зарезервированы. Не вошли: Mason (Emigre, коммерческий), Pusia (ROHH, продаётся на MyFonts), Warcraft III (Friz Quadrata, коммерческий, имена стёрты) и DM Mono (у оригинала нет кириллицы, в моде её дорисовали неизвестно из чего, «ё» сломана). Пересборка: `node scripts/fetch-dota-fonts.mjs` (нужен `unzip`; проверяет латиницу, кириллицу, вес и что лицензия — OFL 1.1).
- «Рисунки в сетке героев не съедут» (16.10.2026; жалоба: с Monocraft и другими «тролльными» шрифтами съезжают рисунки в сетке, просили кнопку «отключить вспомогательные символы @ # % = _ -»). Убрать символы из шрифта нельзя: недостающий знак Dota берёт из системного запасного шрифта, ширина которого разная на разных ПК (как с U+2006, см. `scripts/dota-rendering.mjs`), а рисунки собраны под ширины Radiance Semibold (у Monocraft все знаки по 720/1000 против 229–869 у Radiance). Поэтому переключатель (виден, пока заменяется «Текст», по умолчанию выключен) оставляет файл `radiance-semibold.otf` от Valve: `dotaFontPack(…, { keep: [GRID_FONT_FILE] })` его не пишет, а сайт кладёт в архив оригинал (`assets/fonts/radiance-semibold.otf`, байт в байт как в игре — тем же сайт рисует сетки), чтобы отменить и замену из прошлого архива. Цена: тем же начертанием в Dota написаны и некоторые подписи меню — они тоже останутся обычными.
- Свой шрифт: один или несколько `.ttf`/`.otf`, обрабатываются в браузере, на сервер не уходят. Сайт предупреждает о недостающих буквах; вариативные шрифты, WOFF и коллекции отклоняются.
- Архив собирает `scripts/zip.mjs` (deflate через `CompressionStream`): `fonts/…`, `OFL.txt`, `ПРОЧТИ.txt`.
- Выдача: «Только файл» (по умолчанию) — `gridstudio-font-<шрифт>.zip`, в окне шаги вручную; «Командой PowerShell» (02.10.2026, вместо архива с `.bat` — пользователь: «почему на автоустановку у нас батник») — с 03.10.2026 кнопка называется «Получить команду»: архив отправляется на сайт так же, как фон (`uploadInstallPack`; сервер берёт только ZIP из `fonts/<шрифт Dota>.otf`, `OFL.txt` и «ПРОЧТИ.txt»/`README.txt`, шрифты — с подписью OTF/TTF), и открывается «Как установить» с командой `irm …/api/catalog/install/font-<SHA-256>-<размер> | iex`. Скрипт `fontScript` (`scripts/installer.mjs`, отдаёт `server/grid-installs.mjs`) скачивает этот архив с `…/install/file/font-<SHA-256>` (общий `DOWNLOAD`: размер и SHA-256, 404 — команда устарела), находит Dota, ждёт её закрытия и кладёт из архива только `fonts/<имя>.otf|ttf` (без путей) поверх файлов игры в `game/dota/panorama/fonts`; оригиналы один раз сохраняются в `panorama/fonts/gridstudio-backup` (повторная установка первую копию не трогает), потом удаляется кэш `%TEMP%\fontconfig`. Вернуть — `…/install/font-remove` (`fontRemoveScript`): копия возвращается и удаляется. Под кнопкой скачивания — «Вернуть обычный шрифт» (вместо строки «шрифт · лицензия», 02.10.2026): окно с двумя способами — эта команда и «Файлами» (проверка целостности файлов в Steam или своя копия папки `fonts`, удалить кэш `%TEMP%\fontconfig`). Проверено PowerShell 7 на подставной папке Dota (архив с « (1)» в имени, запись `fonts/../…` пропускается, повторная установка, удаление).
- Превью (`src/customize/FontScene.jsx`, на dev с 02.10.2026) — главное меню и момент матча, разделённые наклонной чертой «/» (тянется мышью, стрелками с ручки). В матче работают таблица счёта (Tab, `, кнопка слева сверху) и магазин (клик по золоту, B), Esc закрывает. Сцены — скриншоты русского клиента 1920×1080 от пользователя (30.09–02.10.2026). Каждая сцена в `src/customize/font-scene.json` + `assets/font-scene/`: «плита» — скриншот без надписей, по слою на роль с родными пикселями надписей (виден, когда роль не заменяется) и сами надписи (`{id, t текст, r роль, w вес, s размер, l letter-spacing, x, y базовая линия, a якорь, c цвет}`), которые SVG `<text>` рисует выбранным шрифтом. Таблица счёта и магазин — только свои области поверх HUD.
- Как получены надписи (рабочая папка вне репозитория: `/home/code/gridstudio/font-scene/`, там же шрифты Valve для подгонки — в сайт и репозиторий они не попадают): опись надписей вручную (текст, грубая рамка, выравнивание, ряды `after`, обрезанные ники `full`/`cut`); стиль каждой — из CSS Панорамы (декомпилированные стили, карты `css-map.json`, `menu-css-map.json`); по пикселям подгоняются только место (начало, базовая линия) и способ округления — нормированной кросс-корреляцией в рамке ±10 px; плита — маска текста +3 px, заполнение «луковицей» и гармонической релаксацией.
- Как Панорама раскладывает текст (измерено 02.10.2026 на этих скриншотах, совпадение с пикселями 0,9–0,99): буквы ставятся по одной, ширина каждой округляется до целого пикселя (на HUD чаще вниз, в меню, магазине и таблице — к ближайшему), плюс letter-spacing; кернинга нет. Текст рисуется на 1 px меньше размера из CSS (16 → 15, 22 → 21). В RadianceM есть только цифры и пробел: остальное — из Radiance, и пробел после такой буквы тоже из Radiance (в «2694 / 2694» широкий пробел RadianceM перед «/» и узкий после). `text-overflow: shrink` уменьшает размер, пока надпись не влезет (золото 22 → 18,5 px); у ников — многоточие. Полупрозрачный текст смешивается в линейном свете, поэтому выглядит ярче и чуть жирнее, чем в браузере.
- Превью повторяет это для выбранного шрифта: ширины букв меряются в браузере и округляются так же, сжатие и многоточие — по ширинам Valve, надписи одного ряда (ник и тег, «(Группа):» и подсказка) сдвигаются вместе. Вертикаль пока — базовая линия Valve; как Панорама ставит шрифт с другими метриками, проверим по скриншотам из игры со своим шрифтом.

Страница скачивает моды с GitHub d2pfx на этом же коммите — поэтому сервер принимает pak04 только из файлов d2pfx байт в байт. Обновить список — запустить скрипт заново.

Dota читает меньший номер первым (pak02 бьёт pak03 — проверено), ни один путь модов не совпадает с нашими pak02/pak03, так что pak04 ничего нашего не перекрывает. - HUD-скины и «Детали HUD» в превью матча (переделка 17.10 по отзыву владельца «криво накладываются, героя обрезает»): **перенос разницы**. `node scripts/make-d2pfx-hud.mjs --s2v <CLI> --playwright <playwright>`:
  1. у каждого мода берутся все файлы Panorama: текстуры (vtex_c → PNG, Source 2 Viewer), стили (vcss_c → исходный текст), разметка (vxml_c → XML);
  2. эмулятор Panorama (`src/customize/panorama`, Vite + Chromium) рисует **весь** HUD в состоянии съёмки (`hudScene({ capture: true })`: без режима для дальтоников, без Alt, цифры съёмки; портрет, миникарта, герой в верхней панели, иконки над инвентарём и врождённая — вырезаны из самой съёмки) на всех снятых масштабах, с подложками и без (F и C), над чёрным и белым: один раз с файлами Valve (E_valve), и для каждого мода с его файлами на их местах (E_mod) — текстуры, стили и разметка вместе;
  3. **регистрация**: для каждой нарисованной панели E_valve ищется сдвиг ±6 px, лучше всего совпадающий со съёмкой; пиксель берёт сдвиг самой маленькой своей панели; слои Valve и модов пересэмплируются этой картой;
  4. сохраняются слои Valve (lossless) и пиксели, которые мод меняет (с запасом 3 px; цвет lossy, альфа точная) — `assets/d2pfx-hud`, ~12 МБ, на экран грузится по 3 файла выбранных модов;
  5. на странице (`scripts/hud-capture/reskin.mjs applyDelta`) к снятым пластинам добавляется разница в линейном свете: b' = b + (b_mod − b_valve), a' = a + (a_mod − a_valve). Там, где мод ничего не меняет, остаются байты Dota — портрет, иконки, цифры. Где E_valve заметно не совпадает со съёмкой (6–24 уровня: текст растрирован иначе, иконка нарисована по-своему) или мод убирает содержимое, пиксель берётся из E_mod — чтобы не было двоения. Слои Chromium (он смешивает в sRGB) переводятся в линейный свет как у Dota (α и цвет из k/w).

# Языки сайта (RU / EN)

С 1.7. Сайт по умолчанию русский; английский — тем, у кого нет признаков кириллической раскладки (русской, украинской, белорусской). Решение пользователя от 01.10.2026.

## Как выбирается язык (`scripts/i18n.mjs`)

Браузер не может перечислить раскладки системы, поэтому признаки такие, по порядку:

1. `?lang=ru` / `?lang=en` в адресе — запоминается (как переключатель).
2. Выбор, сделанный раньше переключателем RU / EN (`localStorage` `gridstudio.lang`).
3. Языки браузера: `ru`, `uk`, `be`.
4. Кириллическая буква, набранная на сайте раньше (`gridstudio.cyrillicKeyboard`; запоминается при любом нажатии).
5. Часовой пояс России, Украины, Беларуси или Казахстана.
6. В Chromium до отрисовки — буквы текущей раскладки (`navigator.keyboard.getLayoutMap`, KeyQ/KeyA/KeyF; ждём не дольше 150 мс).

Ни одного признака — английский. На сервере и в тестах (`location` нет) — русский.

Переключатель — `src/LanguageSwitch.jsx` (RU / EN): в подвалах главной, мастерской, сборщика и в редакторе. Выбор запоминается, страница меняет язык на месте, без перезагрузки (см. «Переключение без перезагрузки»).

## Как устроен перевод

- Тексты в коде остаются русскими. `t('Скачать грид')` возвращает русский текст как есть, а на английском — запись из словаря. Подстановки: `t('Выделено: {count}', { count })` — `{count}` в обоих языках.
- Словари — `src/i18n/en/<область>.js`: `export default { 'Русский текст': 'English text' }`. Они грузятся только для английского (`languageReady` во входном файле страницы), русские пользователи их не скачивают. Области: `common` (общие части: `catalog/Common.jsx`, аккаунт, подвалы, «Что нового»), `landing`, `catalog` (мастерская), `editor-ui` (React-части редактора и студии), `editor` (`scripts/app.mjs` и остальные скрипты редактора), `customize` (сборщик фона), `server` (сообщения сервера и проверок).
- Входные файлы страниц (`src/main.jsx`, `src/catalog/main.jsx`, `src/customize/main.jsx`, `src/landing/{home,main}.jsx`) импортируют приложение и стили статически (порядок CSS важен: динамический импорт приложения ставил его CSS после CSS страницы, и сборщик фона «поплыл»), а рисуют после `languageReady(...)` — для английского сначала грузятся словари.
- Числа и даты — `locale` из `i18n.mjs` (`'ru-RU'` / `'en-US'`) вместо жёсткого `'ru-RU'`.
- Склонения: `plural(n, ['категория', 'категории', 'категорий'], ['category', 'categories'])`, с числом — `tn(n, …)`.
- Сообщения сервера (ошибки API) приходят по-русски; `catalogAPI` переводит их `translateMessage`: сначала точное совпадение в словаре `server`, потом `patterns` — `[[/^Файл (\d+) МБ…$/, 'File $1 MB…']]` для собранных из чисел.
- «Что нового»: у `releases/<версия>.json` есть необязательный `"en"` с английским списком (docs/releases.md); новые выпуски пишутся сразу на двух языках.
- Предложения с разметкой внутри (`<code>`, `<b>`, ссылка) — одной записью словаря: `rich(t('Положи файл {file} в папку'), { file: <code>…</code> })` из `src/catalog/Common.jsx`, а не обрывками.
- Не нашлось в словаре — остаётся русский; `missingTranslations()` в консоли английской страницы перечисляет такие тексты.
- Не переводятся: админка (модерация, правка админом), бот в Telegram, пользовательские названия и описания, `docs/`, комментарии в коде. Превью меню и страниц Dota — картинки русского клиента (переснять с английского — отдельная задача).

## Переключение без перезагрузки

- `setLanguage(lang)` (`scripts/i18n.mjs`): запоминает выбор, для английского догружает словари, вызывает хуки `beforeLanguage`, меняет `lang` / `locale` / `<html lang>`, убирает `?lang=` из адреса и зовёт слушателей `onLanguage`.
- Верхние компоненты страниц подписаны через `useLanguage()` (`src/useLanguage.js`) и перерисовываются целиком; `<title>` из HTML ведёт `followTitle()`.
- Смена плавная: `LanguageSwitch` передаёт в `setLanguage` обёртку `crossfade` — View Transitions растворяют старую страницу в новой за 0,45 с (`html.language-switching` в `src/language-switch.css`); что не изменилось, стоит на месте, меняются только тексты. Поэтому `useLanguage` перерисовывает синхронно (`flushSync`): новый кадр снимается уже на новом языке. Без View Transitions — короткое приглушение страницы, при `prefers-reduced-motion` — без анимации. Подложка под RU / EN переезжает к выбранному.
- Поэтому `t()` нельзя звать при загрузке модуля: константы с текстами — функции (`const PAGES = () => [['menu', t('Меню')], …]`) или русские строки, переводимые там, где рисуются (`t(style.label)`, `translateMessage(label)`). Так устроены таблицы в `scripts/drawing.mjs`, `align-icons.mjs`, `image-settings.mjs`, `text-art.mjs`.
- Редактор (`scripts/app.mjs`) строит много интерфейса один раз, поэтому `StudioFile` (`src/App.jsx`) создаёт его заново: хук `beforeLanguage` сохраняет файл и берёт документ и вид (`getView`: вкладка, инструмент, выделение, панель настроек, масштаб, прокрутка, шаги отмены, скопированное), затем в layout-эффекте на смену языка — новый `StudioLayout` (`key={lang}`) и `createStudio` над тем же открытым хранилищем, `setView`. Без чтения из базы и сети, до отрисовки кадра.
- Проверка: `missingTranslations()` после переключения на английский; пользовательские тексты (имена сеток, названия) остаются как есть.

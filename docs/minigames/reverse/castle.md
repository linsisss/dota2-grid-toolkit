## 1. Шаг симуляции

- Правило. Попап копит реальное время (не больше 0.05 с) и за кадр делает **не больше одного** тика с
  `dt = 1/60` с; при FPS < 60 игра замедляется. Тик идёт только в состоянии боя (не на паузе).
- Доказательство: `FUN_1828b2530`:
  ```c
  acc = (now - last) + acc;  acc = min(0.05, acc);
  if (0.016666666666666666 <= acc) { FUN_1823592c0(game, 0x3c888889 /*1/60*/); acc -= 0.016666666666666666; }
  ```
- Уверенность: высокая.
- Сейчас в порте: `step` — подшаги 1/120 с, сколько нужно на dt кадра.
- Что поменять: фиксированный тик 1/60 (можно догонять несколькими тиками — это отклонение в лучшую сторону,
  но физику считать именно шагом 1/60).

## 2. Физика снаряда: гравитация, сопротивление, ветер

- Правило (явный Эйлер, порядок важен):
  ```
  pos_new = pos + v·dt                        (с проверкой пересечения земли по отрезку, §4)
  vy -= dt · G0(1200) · weapon.m_flGravityMult · obj.gravityMult
  vx += windAccel(50) · wind · dt · obj.windMult          (в головоломке wind = 0)
  v  *= 1 − dt · DragCoeff(0.003) · weapon.m_flDragMult · obj.dragMult
  ```
  Сопротивление — **в секунду, не за тик**: за тик ×(1 − 0.00005), т. е. практически нет.
  Юниты/бочки — то же без оружейных множителей (`FUN_1823241e0`).
- Доказательство: `FUN_1823245f0`:
  ```c
  vy = vy - dt * G0 * weapon->m_flGravityMult(0xcc) * obj->gravMult(0x74);
  vx = game->wind(0x44) * windAccel * dt * obj->windMult(0x7c) + vx;
  FUN_181e256c0(&v, 1.0 - dt * DragCoeff * weapon->m_flDragMult(0xa0) * obj->dragMult(0x78));
  ```
- Уверенность: высокая.
- Сейчас в порте: `accelerate` (l.374): `keep = (1 − 0.003)^(60·dt)` — ×0.997 за 1/60 с (≈ −16 %/с).
- Что поменять: `keep = 1 − dt·0.003·dragMult` (dt в секундах); позицию сдвигать до изменения скорости.
  Проверить проходимость уровней заново: траектории станут заметно длиннее.

## 3. Скорость выстрела и зарядка

- Правило. Заряд растёт `m_flVelocityPerChargeSecond` = 900 ед/с. Мощность
  `p = min(weapon.m_flMaxSpeed, заряд) / Vmax`, где `Vmax` — наибольший `m_flMaxSpeed` среди оружия (1600).
  Скорость снаряда = `weapon.m_flMaxSpeed · p` — у оружия с максимумом < 1600 потолок `max²/1600`
  (граната 1500 → 1406, РГЧ 1400 → 1225). `m_flLockedPower`: `p = locked·maxSpeed` (только плазма).
  Направление — угол возвышения `a` (°) и сторона взгляда `f = ±1`: `v = speed·(f·cos a, sin a)`.
- Доказательство: `FUN_18232ea50`, `FUN_182357a20`:
  ```c
  charge = dt * consts->m_flVelocityPerChargeSecond + charge;
  power = min(weapon->m_flMaxSpeed, charge) / schema->maxSpeedOfAll;   /* schema+0x180 = 1600 */
  FUN_1823227a0(game, muzzle, (weapon->m_flMaxSpeed * sin(a) * power, weapon->m_flMaxSpeed * f*cos(a) * power), ...);
  ```
- Уверенность: высокая.
- Сейчас в порте: `tick` (l.397) — скорость = заряд до `maxSpeed` оружия.
- Что поменять: `speed = maxSpeed · min(maxSpeed, charge) / 1600`.

## 4. Земля, отскок гранаты, скольжение

- Правило. Перемещение за тик проверяется по отрезку (Брезенхем) на маске; при касании снаряд ставится в
  последнюю свободную точку (или ближайшую свободную в радиусе 7 px). Нормаль — по квадрату 5×5 вокруг точки:
  `n = −Σ(смещения твёрдых пикселей)`, нормализованная. Для `m_bBounces`:
  - касание **после полёта** (время в воздухе > 0): `v = (v − 2(v·n)n) · (1 − m_flBounceDrag)` (граната 0.5);
  - касание, когда уже на земле: `v = v − (v·n)n` — скольжение вдоль поверхности, без порога «остановки».
  Не прыгающие снаряды при касании вызывают взрыв (§6).
- Доказательство: `FUN_1823245f0` (ветки разделены `jbe` по 0x182324844 — декомпилятор их склеил),
  `FUN_182326f90`:
  ```c
  if (0.0 < airtime) { FUN_182326f90(shot, 0, weapon); airtime = 0; }        /* отражение */
  else { n = FUN_182de4600(terrain, pos); v = v - n * dot(v, n); }            /* скольжение */
  /* FUN_182326f90: */ v = v - n * (dot(v, n) + dot(v, n)); v *= 1.0 - weapon->m_flBounceDrag;
  ```
- Уверенность: высокая (нормализация нормали — средняя: `FUN_1823477c0` в конце не разобран).
- Сейчас в порте: `ground` (l.537) — отражение с ×bounceDrag, остановка при |v| < 40; `normalAt` (l.171) — круг r 5.
- Что поменять: множитель `1 − bounceDrag`; при непрерывном контакте — проекция на касательную вместо
  отражения; окно нормали 5×5; убрать «покой» (гранату держит на склоне только её собственная проекция).

## 5. Запал гранаты

- Правило. Для оружия с `m_flFuseTime > 0` и `m_bBounces` таймер снаряда держится на 0, **пока снаряд ни разу
  не коснулся земли**; после первого касания он растёт. Взрыв — при касании земли, когда таймер ≥ запала
  (на земле касание каждый тик → ровно через 1.5 с после первого касания; если в этот момент снаряд в воздухе
  после отскока — при следующем касании). В воздухе по запалу граната не взрывается. Столкновений с
  юнитами у гранаты нет (`m_bCollides` false).
- Доказательство: `FUN_18234b4f0`, `FUN_18234b970`:
  ```c
  if ((0 < weapon->m_flFuseTime) && weapon->m_bBounces && !shot->touchedGround(0x108)) shot->timer(0xc4) = 0;
  /* OnHitTerrain: */ if ((fuse <= 0.0) || (fuse <= shot->timer)) { if (--shot->explodesLeft == 0) {...} }
  ```
- Уверенность: высокая.
- Сейчас в порте: `updateShot` (l.512) — запал от выстрела, взрыв и в воздухе.
- Что поменять: запал от первого касания, взрыв только при касании. Отдельно перепроверить «Промеж башен»
  (сложный): комментарий порта говорит, что без взрыва в воздухе уровень не проходится — у Valve он должен
  проходиться иначе (скольжение §4 и почти нулевое сопротивление §2 меняют траектории).

## 6. Взрыв, попадание, урон

- Удар о землю (`FUN_18234b970`): счётчик `m_nExplodeTimes`−1; на нуле — визуальный взрыв и смерть снаряда.
  Каждый удар — `FUN_18232add0`: урон `m_flDamage` всем живым объектам (состояние 0), чей хитбокс пересекает
  круг `m_flDamageRadius`, кроме пар «снаряд–снаряд одной команды»; вырез земли кругом `m_flTerrainCarveRadius`
  (пиксели с центром в радиусе). Затем `v = v·m_vVelocityMultOnExplode + m_vVelocityOffsetOnExplode`, радиусы
  += `m_flRadiusChangePerExplode` (не меньше 0). Совпадает с портом.
- Попадание в объект (`FUN_1823488e0`): столкновения проверяются только между объектами **разных команд** с
  флагом столкновений — свой снаряд никогда не попадает в Снэпфайр напрямую (только взрывом). Хитбокс снаряда —
  круг `m_flHitRadius` (по умолчанию **8**, копатель 1). При попадании снаряд переносится в **центр низа
  хитбокса цели** (x = середина, y = ноги) и взрывается там; без `m_flDamageRadius` — урон только цели.
- Доказательство: `FUN_1823488e0`:
  ```c
  shot->x = (target.min.x + target.max.x) * 0.5;  shot->y = target.min.y;
  if (--shot->explodesLeft == 0) { SetState(1); if (!shot->explodes) target->TakeDamage(weapon->m_flDamage); }
  ```
- Уверенность: высокая (порядок min/max в объекте — средняя).
- Сейчас в порте: `hitsUnit` (l.504) — точка в AABB, своя пушка неуязвима только 0.25 с; взрыв в точке касания.
- Что поменять: снаряд как круг r = `m_flHitRadius` (по умолчанию 8); игрока прямым попаданием не задевать
  вообще; точку взрыва при попадании — в низ-центр цели.

## 7. Урон от падения и смерть за краем

- Правило. При касании земли, если время в воздухе > 0.3 с и у объекта `m_flFallDamagePerVelocity` > 0:
  `speed = |(vx·0.01, vy)|`; если `speed ≥ 50` → урон `speed · m_flFallDamagePerVelocity · 0.002`.
  По умолчанию множитель 1 (Снэпфайр — 1 HP → гибель при speed ≥ 500, ≈ 104 px падения); у **всех врагов и
  бочки в vdata 0** — урона от падения у них нет. Ниже `m_flMinimumGameObjectY` (−300) объект с
  `m_bDestroyOnFallThrough` (по умолчанию да) получает урон health+1.
- Доказательство: `FUN_1823241e0`:
  ```c
  if ((consts->m_flMinAirTimeForDamage < airtime) && (0.0 < obj->fallDmgPerVel)) {
    speed = length(vx * 0.01, vy);
    if (consts->m_flMinVelocityForFallDamage <= speed) obj->TakeDamage(speed * obj->fallDmgPerVel * consts->m_flFallDamageMult); }
  ```
- Уверенность: высокая.
- Сейчас в порте: `land` (l.461) — `(speed − 50)·0.002` всем юнитам, включая врагов.
- Что поменять: формула `speed·k·0.002` без вычитания 50 (50 — только порог), `k` из
  `m_flFallDamagePerVelocity` (игрок 1, враги/бочки 0). Враги гибнут только ниже y = −300.

## 8. Ходьба и патруль врагов

- Правило. Скорость = `5 · 20 · m_flMovementSpeed` = 100 ед/с (по умолчанию 1.0; у врагов в vdata не задано);
  с флагом «точно» ×0.1. Приказ: `t = fmod(m_flTimeOffset + таймер, сумма длительностей)`, берётся приказ, в
  чей отрезок попадает t. Шаг: новая высота — первая свободная точка над ногами; подъём > `m_flMaxClimbHeight`
  (3) — x откатывается. Если позиция не изменилась 5 тиков подряд при движении, враг **перескакивает в конец
  текущего приказа** (таймер сдвигается).
- Доказательство: `FUN_182349f40`, `FUN_182349a70`, `FUN_182358630`, `FUN_1823241e0`:
  ```c
  fVar26 = (slow ? 0.1 : 1.0) * 5.0;   vx = fVar26 * ±20.0 * unit->moveSpeed(0x130);
  if (samePos(pos, lastPos)) stuck++;               /* ArtyEnemy: if (4 < stuck) { stuck = 0; skipOrder(); } */
  if (consts->m_flMaxClimbHeight < newY - oldY) { x = oldX; y = oldY; }
  ```
- Уверенность: высокая.
- Сейчас в порте: `walk` (l.449) — 100 px/с, без пропуска приказа.
- Что поменять: при застревании ≥ 5 тиков сдвигать часы приказов к концу текущего приказа.

## 9. Прицел с клавиш

- Правило. Угол возвышения относительно стороны взгляда ограничен **−15…85°**; W/S (биты 0/1 ввода) меняют
  его на `dt·5.75·5` = 28.75°/с, с Shift ×0.1 (2.875°/с). Ходьбы/разворота с клавиш у игрока нет (биты
  движения не выставляются). Точка вылета: `пушка + (f·70·cos a − 25·sin a, 70·sin a + f·25·cos a)`.
- Доказательство: `FUN_182349f40`, `FUN_18232df20` (ввод игрока), `FUN_18232e120`:
  ```c
  angle = dt * 5.75 * fVar26 + angle; if (85.0 < angle) angle = 85.0;     /* вниз: max(-15, …) */
  out.x = sx * cos(a) * f + base.x + -sin(a) * sy;  out.y = sx * sin(a) + base.y + cos(a) * f * sy;
  ```
- Уверенность: средняя — мышь/касание (поворот стороны) не прослежены; клавиатура — высокая.
- Сейчас в порте: `turnAim` (l.276) — 60°/с, Shift ×0.2, полный круг; `muzzle` (l.261) зеркалит смещение
  по-другому при взгляде влево (знак у 25·sin a).
- Что поменять: ограничить возвышение −15…85° от стороны взгляда, 28.75°/с и ×0.1; формула точки вылета выше.

## 10. Бонус за время и очки уровня

- Правило. Таймер уровня стартует с первого потраченного снаряда игрока и идёт тиками до объявления
  победы. Очки: строки «за каждое оружие: остаток × m_nWeaponPoints», `m_nLevelCompletePoints`, бонус:
  ```
  B = Base, M = Max, F = FastTime, T = MaxTime (длительность ПОСЛЕ F)
  t ≤ F: bonus = B + trunc(lerp(M−B, 0.9·(M−B), t/F))
  t > F: bonus = B + trunc(lerp(0.9·(M−B), 0, clamp((t−F)/T, 0, 1)))
  ```
  Для всех уровней B 300, M 400: 400 в момент 0 → 390 к F → 300 к F+T и **300 навсегда** (не 0).
- Доказательство: `FUN_1828d6cd0` (дизассемблер 0x1828d6f5a…0x1828d6fcb, константа 0.9 по 0x183cd7a38):
  ```asm
  xmm3 = float(M) - float(B); xmm1 = xmm3 * 0.9; comiss F, t; jae short
  ; t > F:  Remap(t - F, 0, T, xmm1, 0)      ; t <= F: Remap(t, 0, F, M - B, xmm1)
  points = (int)Remap(...) + B
  ```
- Уверенность: высокая.
- Сейчас в порте: `timeBonus` (l.122) — 400 до F, линейно до 300 к T (абсолютному), после T — 0; конец
  таймера — момент гибели последнего врага (`kill`, l.483).
- Что поменять: формула выше; таймер останавливать в момент объявления победы (§11), это ≈ +1.1 с.

## 11. Победа, поражение, «снаряды кончились»

- Правило. Каждый тик (если исход ещё не решён): если хоть один объект в состоянии ≠ 0 (кто-то умирает) —
  ждать. Иначе: игрок есть и врагов (тип 5, команда 2) нет → победа; игрока нет → поражение «Вы погибли».
  Летящие снаряды победе не мешают. Значение 3 («Снаряды закончились») в клиенте **нигде не присваивается** —
  при пустом боезапасе уровень сам не заканчивается: кнопка перезапуска мигает (класс NoAmmo), пользователь
  перезапускает сам.
- Доказательство: `FUN_1823592c0` (хвост, дизассемблер 0x18235969b…0x182359717):
  ```asm
  cmp [rcx+0xc0],0 ; cmovne busy      ; тип 4 → hasPlayer ; тип 5 и команда 2 → enemies++
  test busy ; jne done ; test hasPlayer ; je lost ; test enemies ; jne done
  mov [rbx+8], 1 (won) ; ... lost: mov [rbx+8], 2
  ```
  Поиск по client.dll: записей 3 в поле исхода (`game+8` / `popup+0x238`) нет; строка
  `LevelLost_OutOfAmmo` только читается в `FUN_1828d5860`.
- Уверенность: высокая (победа/гибель), средняя–высокая («кончились» — доказательство отсутствием).
- Сейчас в порте: `judge` (l.589) + `futureDeaths` (l.608) — свой прогноз на 20 с и проигрыш «кончились».
- Что поменять: победа — когда нет живых врагов и никто не умирает (вместо 1.2 с ожидания). Авто-проигрыш
  по снарядам можно оставить как удобство, но пометить «наше»; ближе к оригиналу — не заканчивать уровень,
  а мигать перезапуском.

## 12. Открытие уровней и сложного режима

- Правило. Уровни режима открываются по порядку: ячейка доступна, пока у всех предыдущих уровней этого
  режима счёт > 0 (первый ноль закрывает все следующие). Сложный режим (вкладка) открыт, когда на **каждом**
  уровне обычного режима есть хотя бы одна звезда (счёт ≥ первого порога). Звёзды = число порогов ≤ счёта;
  хранится лучший счёт уровня.
- Доказательство: `FUN_1828a9080` (`SetEnabled(flag); if (flag && score < 1) flag = 0;`), `FUN_1828b2530`
  и `FUN_1828c8cd0` (цикл по уровням `crownfall_act4`: `stars == 0 → bVar5 = false` → иначе `FUN_1828d01a0`,
  снимающий HardModeDisabled).
- Уверенность: высокая.
- Сейчас в порте: `levelOpen` (l.658), `hardUnlocked` (l.656), `recordResult` (l.648) — совпадает.
- Что поменять: ничего.

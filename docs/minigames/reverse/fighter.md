# «Сосулечный боец» (fighter, Valve: fighting) — разбор client.dll

Бинарник: client.dll 107 533 976 байт, SHA-256 dfec84e4…ceefd6, депо 373303, манифест 5121451448605799518
(2026-10-15).

Где логика. Вся симуляция — в `CDOTAFightingGameController` (0x182a40000–0x182ac0000), без виртуальных методов;
объект игры (`game`) и кадр состояния (`state`, откатываемый при rollback, CRC каждого кадра) — свои структуры.
Боец — 0x218 байт, два подряд с `state+0x14`. Поля бойца: `+0x188` сторона, `+0x18c` герой, `+0x190` x,
`+0x198` x прошлого кадра, `+0x1a0` направление (±1), `+0x1a4` скорость шага вперёд, `+0x1a8` назад, `+0x1ac`
действие (`EFightingGameActionID`: IDLE 0, BLOCKSTUN 1, HITSTUN 2, KNOCKED_DOWN 3, DASH 4, BACKDASH 5,
GUARDBREAK 6, VICTORY 7, DEFEAT 8, … SWAP 26), `+0x1b0` кадр действия, `+0x1b4` кадр конца действия, `+0x1b8`
макс. здоровье, `+0x1bc` здоровье, `+0x1c0` защита, `+0x1c4` хитстоп, `+0x1c8/+0x1cc` кадры/путь отталкивания,
`+0x1d4` кадры install, `+0x1d8/+0x1dc` кадры/процент усиления урона, `+0x1e4` кадр последнего действия/ввода,
`+0x1e8` отложенная отмена, `+0x214` флаги (0x10 блок, 0x20 шаг вперёд, 0x40 шаг назад, 0x08 одноразовый приём
израсходован, 0x80 приём попал/заблокирован), `+0x215` (0x02 защита сломана).

## 1. Здоровье, защита, шаг — константы бойца

- Правило. Одинаково для всех героев (из vdata не читается): здоровье 1000, защита 100, шаг вперёд **6** ед./кадр,
  назад **5** ед./кадр. В начале раунда: x = −500 / +500 (не ±450), направление +1 / −1, здоровье и защита полные,
  флаг «одноразовый приём израсходован» и «защита сломана» сброшены, install = −1, усиление урона 0.
- Доказательство: `FUN_182a5a030`, `FUN_182aaabc0`:
  ```c
  param_1[0x69] = 0x40c00000;  /* +0x1a4 = 6.0 */   param_1[0x6a] = 0x40a00000;  /* +0x1a8 = 5.0 */
  param_1[0x6e] = 0x447a0000;  param_1[0x6f] = 0x447a0000;  /* 1000, 1000 */
  *(undefined8 *)(param_1 + 0x70) = 0x42c80000;              /* защита 100, хитстоп 0 */
  ... state+0x1a4 = 0xc3fa0000 /* −500 */; state+0x3bc = 0x43fa0000 /* +500 */
  ```
- Уверенность: высокая.
- Сейчас в порте: `RULES.maxHp 1000`, `maxGuard 100` (совпадает); `walkForward 5`, `walkBack 4`; старт ±450
  (`resetRound`, строка 151).
- Что поменять: `walkForward: 6`, `walkBack: 5`; старт `±500`.

## 2. Восстановление защиты и слом

- Правило (каждый кадр боя, пока раунд не закончен, для бойца не в BLOCKSTUN/HITSTUN/KNOCKED_DOWN/GUARDBREAK):
  `guard = min(100, guard + (сломана ? 20 : 3) / 60)`. **Задержки нет**: обычная скорость 3 ед./с (0→100 за
  33 с), сломанная — 20 ед./с (0→100 за 5 с); флаг «сломана» снимается, когда защита дошла до 100.
- Блок: `guard -= m_flGuardDamage` (если не `dota_fg_infinite_block` и защита ещё не сломана); защита ≤ 0 →
  «сломана». Chip-урон (`m_flChipDamage × (100 + усиление%)/100`) снимается при каждом блоке, в том числе
  ломающем.
- Ломающий удар и любой «блок» при уже сломанной защите обрабатываются как попадание с уроном
  `m_flHitDamage × dota_fg_guard_break_damage_multiplier (1.2)`, хитстоп `m_nHitStop`, отталкивание
  `m_flPushbackOnBlock`; цель переходит в GUARDBREAK на `m_nDuration` этого действия (у всех героев 30) — без
  добавки `m_nOnBlockFrames`. Если цель со сломанной защитой не держит блок — обычное попадание ×1.0 и HITSTUN.
  Т. е. ×1.2 действует только на удары, которые пытаются заблокировать при сломанной защите.
- Доказательство: `FUN_182aadde0` (регенерация), `FUN_182aa08f0` (блок):
  ```c
  if ((2 < action - 1U) && (action != 6)) {
    fVar12 = 3.0; if ((bVar1 & 2) != 0) fVar12 = 20.0;
    guard = min(100.0, fVar12 / 60.0 + guard);  if (100.0 <= guard) flags &= ~2; }
  ...
  if (!infinite_block && !(bVar4 & 2)) { guard -= act->m_flGuardDamage; if (guard <= 0) flags |= 2; }
  hp = max(0, hp - ampMult * act->m_flChipDamage);
  if (flags & 2) FUN_182a67cb0(game, hit, trade, cvar_guard_break_mult);   /* 1.2 */
  ```
- Уверенность: высокая.
- Сейчас в порте: `guardRegenDelay 60`, `guardRegen 0.5`/кадр (30/с), `brokenGuardRegen 0.4`/кадр (`simulate`,
  строки 411–413); ломающий удар — только chip + GUARDBREAK (`applyHit`, 467–474); при сломанной защите
  `blocks()` → false и **все** попадания ×1.2 (строка 482).
- Что поменять: регенерация без задержки 3/60 за кадр, сломанная — 20/60, и только вне стана/GUARDBREAK;
  ломающий удар — урон ×1.2 + GUARDBREAK; при сломанной защите удержание «назад» → урон ×1.2 и снова
  GUARDBREAK (30 кадров), без удержания — обычный удар ×1.0.

## 3. Блок

- Правило. Флаг блока ставится каждый кадр, если боец в BLOCKSTUN (автоматически, без удержания) или в IDLE и
  держит «назад» без «вперёд» (в том числе с «вниз»). «Вперёд» важнее «назад», если зажаты оба. Во время
  собственного хитстопа флаг не ставится (сбрасывается до выхода по хитстопу).
- Шаг назад с блоком отменяется (стоит на месте), если хёрт-бокс бойца ближе 20 ед. к хитбоксу **текущего
  действия** соперника (`m_HitBox` в мировых координатах, на любом кадре действия, не только активном).
  Снаряды на это не влияют.
- Доказательство: `FUN_182a9a2e0` (флаги), `FUN_182a9acb0`:
  ```c
  if (action == 1) flags |= 0x10;                                   /* BLOCKSTUN */
  ... if (fwd == -1 && back != -1) { if (down == -1) flags |= 0x40; flags |= 0x10; }
  if ((flags & 0x50) == 0x50) { /* хитбокс соперника ±20 пересекает мой хёрт-бокс */ flags &= 0xbf; }
  ```
- Уверенность: высокая.
- Сейчас в порте: блок только при удержании «назад» в IDLE/BLOCKSTUN (`blocks`, 446–452); стойка на месте —
  если соперник атакует ближе 950 или летит снаряд ближе 700 (`control`, 290–292); «вниз+назад» идёт назад.
- Что поменять: в BLOCKSTUN блокировать всегда; стоять на месте по правилу «хитбокс действия соперника + 20»;
  «вниз+назад» — блок без шага; при «вперёд+назад» — шаг вперёд.

## 4. Рывки (DASH / BACKDASH) и рывки внутри приёмов

- Правило двойного касания (проверяется в IDLE, когда «вперёд» зажат сейчас; для «назад» зеркально):
  окно `lower = max(кадр последнего действия + 1, now − 8)`; последнее нажатие «вперёд» до паузы (кадр `p`) должно
  быть в окне, перед ним в пределах 8 кадров — кадр без «вперёд» (первое касание ≤ 8 кадров), между ним и
  текущим кадром — хотя бы один кадр без «вперёд» (поиск с now−2, т. е. при паузе в 1 кадр срабатывает на кадр
  позже), и **никаких** «назад/вверх/вниз» (без «вперёд») после `p`. Тогда SetAction(DASH) (BACKDASH).
- Скорость: DASH/BACKDASH двигают через флаг шага на всех кадрах действия, где нет хитстопа, включая кадр 0:
  `шаг_вперёд(6) × m_flDashSpeedMultiplier` (назад `5 × mult`). Марси (mult 4): 15 кадров × 24 = 360 вперёд,
  15 × 20 = 300 назад.
- Рывок внутри приёма (`m_nDashStart/m_nDashDuration`): `x += mult × 6 × facing` на кадрах
  `DashStart < frame < DashStart + DashDuration` (строго, т. е. Duration − 1 кадр); без `m_nDashDuration` (−1) —
  не двигает. Проверка не учитывает хитстоп (во время хитстопа рывок продолжается — особенность Valve).
- Доказательство: `FUN_182a9a2e0` (детектор, ветки с `FUN_182a7f7d0(... iVar13 + -8 ...)` → SetAction 4/5),
  `FUN_182a9acb0`:
  ```c
  if (-1 < dashStart && dashStart < frame && frame < dashStart + dashDur)
    x += act->m_flDashSpeedMultiplier * walkFwd * facing;
  if (flags & 0x20) x += (action == 4 ? mult : 1.0) * walkFwd * facing;
  else if (flags & 0x40) x -= (action == 5 ? mult : 1.0) * walkBack * facing;
  ```
- Уверенность: высокая (детектор — средняя по деталям окна в 1 кадр).
- Сейчас в порте: `dashTapWindow 12`, `dashTapHold 10` (`record`, 193–197); скорость `dashUnit 5 × mult`
  (строка 349) для обоих направлений; при `len < 0` рывок до конца приёма.
- Что поменять: окно 8 кадров по правилу выше, сброс по любому другому направлению; скорость DASH `6 × mult`,
  BACKDASH `5 × mult`, на всех 15 кадрах; рывок приёма — `6 × mult`, кадры `start < t < start + len`, без len —
  нет движения.

## 5. Ввод: окна моушенов, буфер, отмены

- Задержка ввода: ввод человека пишется в кадр `now + dota_fg_delay_frames` (3) и в одиночной игре; ИИ — в
  текущий кадр (без задержки).
- Окно варианта отмены: **8 кадров на каждый элемент ввода** (1 элемент — 8, 2 — 16, 3 — 24), вся
  последовательность должна уложиться в это окно и начаться после `+0x1e4` (кадр начала текущего действия или
  предыдущего распознанного ввода — одно нажатие используется один раз). Последний элемент с кнопкой: кнопка
  нажата (есть кадр без неё перед нажатием) в окне; для 3-элементных (`m_eCancelInput3`) последний элемент
  должен быть зажат именно в текущем кадре. Каждый ранний элемент — «нажат» (с кадром без него перед этим)
  раньше следующего. Совпадение направлений — «содержит» (вниз+назад годится для «вниз»). Варианты
  проверяются по порядку vdata, первый подошедший запоминается (`+0x1e8`).
- `m_nCancelInputBuffer` в vdata **не задан ни разу**: в файлах ключ называется `m_eCancelInputBuffer`, такой
  строки в client.dll нет → поле остаётся −1, и ограничения «ввод с `CancelStart − Buffer` до
  `CancelStart + Duration`» нет. В итоге: нажатие в любой момент приёма (после его начала) запоминается, отмена
  срабатывает на первом кадре `≥ m_nCancelStart` (без start — сразу), если к этому кадру приём попал или
  заблокирован (`+0x214 & 0x80`), или `m_bAllowCancelOnWhiff`, или у приёма нет хитбокса; иначе запомненная
  отмена выбрасывается (нажатие израсходовано). `m_nCancelDuration` задан только у fallback (2): отмена
  исполняется при `frame ≥ start + duration` (так в коде; на реальных героях не влияет).
- Из IDLE: варианты IDLE без старта — срабатывают сразу; буфер в IDLE — те же 8 кадров назад, в том числе
  нажатия за последние 8 кадров стана (SetAction в стан обновляет `+0x1e4`, поэтому раньше — нет).
- `m_bRequiresInstall`: нужен `install > 0` (или `dota_fg_force_install`).
- Доказательство: `FUN_182a9a2e0`, `FUN_182a945e0`:
  ```c
  iVar4 = (opt->input2 == 0) ? 8 : 16;  iVar5 = (opt->input3 == 0) ? iVar4 : iVar4 + 8;
  if (FUN_182a945e0(f, opt, game, iVar5)) { f->pendingCancel = i; f->lastInputFrame = now; break; }
  ...
  if (start <= frame && (start + dur <= frame || dur == -1)) {
    if (opt->allowOnWhiff || act->m_nHitBoxStart == -1 || (f->flags & 0x80)) SetAction(f, opt->actionID);
    f->pendingCancel = -1; return; }
  ```
- Уверенность: высокая (поведение `m_nCancelDuration` — средняя, на игру не влияет).
- Сейчас в порте: окно 16 кадров на шаг (`motionWindow`), буфер IDLE 4 (`idleBuffer`), окно отмены
  `[start, start+len)` с буфером `m_eCancelInputBuffer` (6) (`chooseMove`, 266–277); ввод без задержки.
- Что поменять: окно `8 × число элементов` на всю последовательность; буфер IDLE 8; отмена — запомнить нажатие
  в любой момент приёма, исполнить на кадре `≥ CancelStart` при попадании/блоке (или whiff/без хитбокса), иначе
  сбросить; буфер из vdata не использовать. По желанию — задержка ввода человека 3 кадра.

## 6. Попадание, стан, хитстоп, отталкивание

- Активные кадры хитбокса: `HitBoxStart ≤ frame ≤ HitBoxStart + HitBoxDuration` (включительно: на 1 кадр больше,
  чем `m_nHitBoxDuration`); пересечение коробок — нестрогое (≤). Одно попадание на приём (флаг 0x80).
- Неуязвимость: `InvulnStart ≤ frame < InvulnStart + InvulnDuration`; SWAP проходит сквозь STRIKE-неуязвимость.
- Стан: попадание `+0x1b4 = m_nOnHitFrames + (конец действия атакующего − его кадр)`, блок — с `m_nOnBlockFrames`.
  У снаряда остаток = **0**: стан ровно `m_nOnHitFrames` / `m_nOnBlockFrames` (25/15 у Бристлбэка, 25/10 у
  Бивня, 40/15 у Шен).
- Хитстоп: обоим (и владельцу снаряда) `m_nHitStop` при попадании/сломе, `m_nBlockStop` при блоке; у каждого
  бойца свой счётчик, во время него его действие не идёт и шага нет; снаряды летят дальше.
- Отталкивание (`FUN_182a681b0`): добавляется к остатку, расходуется **равными долями за 4 кадра**; ограничено
  расстоянием до края сцены позади цели (центр, ±1250); недостающее у стены отталкивает атакующего (если не
  `m_bNoAttackerPushback`, без дальнейшей передачи). При попадании — `m_flPushbackOnHit`, при блоке и сломе —
  `m_flPushbackOnBlock`. KO-удар отталкивает обычным `PushbackOnHit` (отдельного отлёта нет).
- Урон: `m_flHitDamage × (100 + усиление%)/100 × множитель`; усиление (`m_nDamageAmpFrames/m_fDamageAmpPercent`)
  ставится цели **до** расчёта урона этого же удара и умножает и chip. `m_flHealOnDamage` лечит атакующего
  (до максимума) при каждом попадании, без условия «урон > 0».
- Обмен ударами: попадания одного кадра применяются оба.
- Доказательство: `FUN_182ab6b10` (коробки), `FUN_182aa08f0`, `FUN_182a9a2e0`:
  ```c
  if ((hitStart <= frame) && (frame <= act->m_nHitBoxDuration + hitStart)) /* хитбокс в списке */
  remaining = (att->actionEnd < 1) ? 0 : att->actionEnd - att->frame;   /* у снаряда 0 */
  def->actionEnd = (blocked ? act->m_nOnBlockFrames : act->m_nOnHitFrames) + remaining;
  step = f->pushLeft / max(f->pushFrames, 1); f->pushFrames--; f->pushLeft -= step; x -= step * facing;
  ```
- Уверенность: высокая.
- Сейчас в порте: активны `hitLen` кадров (строка 374); снаряд — «как будто попал при броске»
  (`applyHit`, 458); общий `game.freeze` (останавливает и снаряды); отталкивание 8 кадров треугольником
  (353), KO — отлёт 250 за 16 кадров (507); усиление ставится после урона; лечение только при уроне > 0.
- Что поменять: активные кадры `≤ start + len`; стан снаряда = `onHit/onBlock`; хитстоп по бойцам (снаряды не
  останавливать); отталкивание 4 равных кадра; убрать KO-отлёт; усиление — до расчёта урона, и на chip.

## 7. Тела: ширина, края, макс. дистанция

- Правило (`FUN_182aa04b0`, после движения):
  1) x каждого бойца ограничен центром сцены `±stage_width/2` (±1250), без учёта ширины.
  2) `|x0 − x1| > dota_fg_max_hero_distance (1400)` → бойцам с флагом шага назад вернуть прошлый x; если всё ещё
     больше — оба ставятся симметрично от середины на расстоянии ровно 1400.
  3) Минимальная дистанция центров = `m_flHeroWidth(герой0) + m_flHeroWidth(герой1)` (Марси × Марси 400,
     Бивень × Бивень 550 — не половины!). При заходе: если шагает вперёд (флаг 0x20: шаг или DASH) только
     один — он толкает: толкаемый ставится на `сумма − |шаг толкающего|/2` от толкающего (если толкаемый
     шагает назад — на `сумму`), затем толкающий — ровно на `сумму` от толкаемого (оба с ограничением сценой);
     скорость толкания — половина шага. Если вперёд идут оба или никто (например, отталкивание) — оба
     возвращаются на прошлые x.
- Направление бойцов не меняется в течение раунда (только SWAP меняет местами x и направления), тела не
  проходят друг сквозь друга.
- Доказательство: `FUN_182aa04b0`:
  ```c
  fVar12 = heroDef0->m_flHeroWidth + heroDef1->m_flHeroWidth;
  if (sign((xR - xL) * facingL - fVar12) != sign(facingL)) {        /* пересеклись */
    if (!(L & 0x20) && (R & 0x20)) { d = (L & 0x40) ? fVar12 : fVar12 - |R.dx| * 0.5;
      xL = clamp(xR + d * facingR); xR = clamp(xL + facingL * fVar12); }

  ```
- Уверенность: высокая.
- Сейчас в порте: `separate` — `(w0 + w1)/2 × 0.8` (≈160 вместо 400) и расталкивание пополам (422–430); край
  `±(1250 − width/2)` (`clampStage`); макс. дистанция — взвешенный сдвиг (366); поворот лицом в IDLE (341).

  Это заметно меняет дистанции ударов (джеб 425 у Марси достаёт только при сближении вплотную к 400).

## 8. Снаряды

- Правило: появляется на кадре `== m_nHitBoxStart`, только если у бойца нет живого снаряда (один на бойца);
  коробка = мировой хитбокс приёма на момент броска (без сдвига), скорость `facing × m_flProjectileSpeed / 60`
  за кадр. Исчезает, когда центр пересёк точку `центр_при_броске + range × facing` (при `range ≤ 0` — дальний
  край сцены ±1250), при попадании/блоке, при встрече со снарядом соперника (оба). Летит и во время хитстопа.
  Если цель неуязвима к снарядам и снаряд её миновал — он больше не может попасть (флаг 0x02).
- Доказательство: `FUN_182ab6b10`:
  ```c
  else if ((frame == hitStart) && (f->projAction == -1) && !(f->flags & 1)) {
    f->projBox = hitBoxWorld; f->projVel = facing * act->m_flProjectileSpeed;
    f->projEnd = (act->m_flProjectileRange <= 0) ? stageWidth * facing * 0.5
                                                   : center(projBox) + act->m_flProjectileRange * facing; }
  ```
- Уверенность: высокая.
- Сейчас в порте: старт `x + 60 × facing` (`spawnProjectile`, 439), сколько угодно снарядов, граница
  `±(1250 + 200)`, останавливаются в `freeze`.
- Что поменять: без сдвига 60, не больше одного снаряда на бойца, конец полёта по правилу выше.

## 9. Особые приёмы: SWAP, одноразовые, install

- SWAP (Низший обмен): при попадании **или блоке** меняет местами x (и прошлые x) и направления; урона,
  хитстопа и отталкивания нет, цель получает обычный HITSTUN/BLOCKSTUN по `onHit/onBlock + остаток`.
  Расходуется (одноразовый) только при попадании/блоке; промах не тратит.
- UNLEASH (Потаённая сила): расходуется, когда дошёл до `m_nInstallStart` (50) и включился install
  (`+0x1d4 = 5940`); прерванный раньше — не тратится.
- SetAction израсходованного одноразового приёма молча не выполняется (ввод при этом съедается). Флаг
  сбрасывается в начале каждого раунда.
- Доказательство: `FUN_182aa08f0` (`if (act->m_nActionID == 0x1a) { swap x/prev/facing; att->flags |= 8; }`),
  `FUN_182a9a2e0` (`if (InstallFrames > 0 && frame == InstallStart) { install = InstallFrames; if (SingleUse)
  flags |= 8; }`), `FUN_182a6e880` (`if (!act->m_bSingleUse || !(flags & 8) || practice) { … }`).
- Уверенность: высокая.
- Сейчас в порте: расход при старте приёма (`start`, 240); SWAP только при попадании (495).
- Что поменять: SWAP срабатывает и в блок, тратится при контакте; UNLEASH тратится на кадре install.

## 10. KO, нокдаун, раунды, матч

- Нокдаун — **только** при KO (здоровье ≤ 0 после удара или chip): KNOCKED_DOWN на 180 кадров. Других
  нокдаунов нет (подсечки и концовки — обычный HITSTUN).
- KO: обоим хитстоп `dota_fg_ko_stop_frames` (60), конец раунда через 180 кадров после KO. Время вышло: обоим
  хитстоп 180 (convar `time_out_stop_frames` не используется), конец через 180 кадров.
- Итог раунда: KO одного — победа другого; оба KO — ничья; по времени — у кого больше здоровья; **ничья даёт
  победу в раунде обоим** (`round_winner = −1`, оба `+1`).
- Конец раунда: победитель — VICTORY, проигравший (если в IDLE) — DEFEAT; ждём, пока кадр VICTORY ≥
  `m_nVictoryDuration` героя (при ничьей — сразу), затем матч окончен, если у кого-то ≥ 2 побед, иначе новый
  раунд. Предела 5 раундов нет — максимум 3 (каждый раунд даёт победу хотя бы одному); 2:2 → «Ничья» матча.
- Фазы: вступление 720 кадров, пропускается нажатием атаки или способности любым бойцом; начало раунда —
  `round_start (180) + pre_round_start (180)` в первом раунде, 180 в остальных; «Fight!» за 80 кадров до боя;
  конец матча 240 кадров.
- Perfect — только при KO и полном здоровье победителя (ролик и реплика), **очков не даёт**.
- Доказательство: `FUN_182aadde0`, `FUN_182aa9e70` (состояние 3), `FUN_182aadbd0`, `FUN_182aae3f0`:
  ```c
  else { /* кто-то ≤ 0 */ "fighting_game.ko"; state->roundEnd = now + 0xb4; f->hitstop = cvar_ko_stop; }
  if (f0.hp <= f1.hp) { wins1++; winner = 1; }  if (f1.hp <= f0.hp) { wins0++; winner = 0; }
  if (f1.hp == f0.hp) winner = -1;
  if ((roundsToWin <= wins0) || (roundsToWin <= wins1)) next = 4; else next = 1;   /* roundsToWin = 2 */
  ```
- Уверенность: высокая.
- Сейчас в порте: `maxRounds 5`, ничья раунда — никому (`endRound`, 526–529); `koFrames 150` + отлёт;
  `roundEndFrames 60`; вступление 300; Perfect +500 и в т. ч. по времени.
- Что поменять: ничья раунда → обоим победа, максимум 3 раунда, ничья матча возможна; KO: 60 кадров стоп,
  всего 180, нокдаун 180; после — поза победы `victoryDuration`; первый раунд 360 кадров отсчёта; Perfect без
  очков и только при KO.

## 11. Очки

Запись очков на бойца (7 int от `game+0x8c + сторона×0x1c`): время, здоровье, First Blood, Counter, Punish,
стильная концовка, урон; плюс общий итог `game+0xc4 + сторона×4`.

| Событие | Очки | Когда |
|---|---|---|
| First Blood | 200 | попадание с уроном > 0, когда **оба** на полном здоровье и это не обмен ударами (в кадре одно попадание) |
| Counter Hit | 100 | попадание (не блок, урон > 0) по цели, чьё действие имеет хитбокс (`HitBoxStart ≠ −1`) или DASH, на кадре ≤ `HitBoxStart + HitBoxDuration` (разгон и активные) |
| Punish | 100 | то же, но кадр цели > `HitBoxStart + HitBoxDuration` (восстановление) |
| Урон | `int(урон × 0.5)` | каждое попадание (в т. ч. ×1.2 при сломе); chip не считается |
| Стильная концовка | 500 | KO ударом с `m_bIsSpecialMove` (и chip-KO таким приёмом) |
| Время | `round(1000 × оставшееся_время / 60 с)` | победителю раунда (при ничьей — обоим); по времени — 0 |
| Здоровье | `round(1000 × hp_бойца0 / 1000)` | то же (Valve берёт здоровье **бойца 0** для обоих — для одиночной игры это здоровье пользователя) |
| Бонус 2:0 | +1000 к «времени» и +1000 к «здоровью» | победителю матча 2:0 |

- First Blood/Counter/Punish/урон добавляются в итог сразу; время, здоровье и стильные — в конце матча, **обоим
  сторонам и независимо от исхода матча** (раунды, выигранные проигравшим, тоже считаются). Разбивка в конце
  матча: `time_score`, `health_score`, `special_move_finish`, `subtotal` = их сумма, `total` = итог бойца 0.
  Оценка чистого прохождения: ≈ 2×667+1000 + 2×700+1000 + 1000 (урон) + 400 (FB) + приёмы ≈ 6–6,5 тыс. за матч,
  ≈ 30–32 тыс. за 5 матчей — как в гайдах.
- Доказательство: `FUN_182a67cb0`, `FUN_182aa08f0`, `FUN_182aa9e70`:
  ```c
  if (!trade && att.hp == att.max && def.hp == def.max && 0 < dmg) { rec[att].firstBlood += 200; total += 200; }
  rec[att].damage += (int)(dmg * 0.5); total += (int)(dmg * 0.5);
  if (def.frame > defAct->m_nHitBoxStart + defAct->m_nHitBoxDuration) punish += 100; else counter += 100;
  time += roundf(remaining_s / (roundFrames / 60.0) * 1000.0); health += roundf(f0.hp / f0.max * 1000.0);
  if (wins[s] == 2 && wins[other] == 0) { rec[s].time += 1000; rec[s].health += 1000; }
  ```
- Уверенность: высокая (формулы); средняя — что HUD-флаг `.FirstFight` только прячет разбивку.
- Сейчас в порте: `SCORE = { firstBlood 200, counterHit 100, punish 100, perSecond 25, perHealth 1, stylish 500,
  perfect 500 }`; FB на первом попадании раунда, Counter/Punish требуют атаку цели и считают install; урона нет;
  время `25 × ceil(с)`; бонуса 2:0 нет; время/здоровье/стильные только при победе в матче (`matchScore`, 543–549).
- Что поменять: FB по условию «оба полные, не обмен»; Counter/Punish по хитбоксу/DASH цели; добавить
  `int(урон/2)`; время `round(1000 × t/60)`; бонус 2:0 (+1000/+1000); убрать Perfect +500; начислять время,
  здоровье и стильные за все выигранные раунды и при проигранном матче.

## 12. Сюжет (arcade)

- Порядок: все герои кроме выбранного (список меню: Марси 136, Рассветная 135, Шен 20, Бристлбэк 99, Бивень
  100) перемешиваются Фишером–Йейтсом, выбранный герой — последним (двойник). Места на карте
  (`arcade_map_opponent_pos_*`) тоже перемешиваются.
- Уровни ИИ по номеру соперника: `[EASY, EASY, MEDIUM, MEDIUM, HARD]` (EASY 0, MEDIUM 1, HARD 2; −1 — человек).
- Продолжений 3. Счёт сюжета хранится в меню (`+0x580`, 0 в начале) и передаётся новому матчу как стартовый
  итог бойца 0; после победы сохраняется итог матча. После поражения с продолжением счёт **не меняется** —
  очки проигранного матча теряются. Конец игры без продолжений: `final_score` = третий аргумент события
  `DOTAFightingGameMatchWon` (итог победителя, т. е. ИИ — похоже на ошибку Valve), рекорд сравнивается с ним.
- Доказательство: `FUN_182e6f7e0` (`FUN_182e83c70(...,0x88/0x87/0x14/99/100)`, массив `{0,0,1,1,2}`),
  `FUN_182e8bfb0` (перемешивание, `+0x60c = 3`), `FUN_182e83970`:
  ```c
  if (won) { arcade->score = score; stage++; if (stage < n) { opponent = order[stage]; ai = levels[stage]; } }
  else if (continues != 0) { state = CONTINUE; continues--; }   /* score не трогаем */
  ```
- Уверенность: высокая (порядок, уровни, 3 продолжения); средняя — смысл аргументов события на поражении.
- Сейчас в порте: `ARCADE` (5 соперников, 3 продолжения, те же уровни) — совпадает; `arcadeResult` прибавляет
  `subtotal` и при поражении.
- Что поменять: при поражении не прибавлять очки матча (откат к счёту после последней победы); итог сюжета —
  накопленный счёт пользователя (ошибку Valve с итогом ИИ не повторять).

## 13. ИИ (EASY / MEDIUM / HARD)

- Общее: решение принимается, только когда боец в IDLE и прошлое решение истекло; решение — «держать эти кнопки
  до кадра N» (очередь). Не в IDLE → ничего не жмёт (комбо и отмены ИИ не делает: кнопку держит, а не нажимает
  заново). Задержки реакции нет; ввод ИИ без задержки 3 кадра.
- Данные: `dist = |x_я − x_соп|`; по вариантам IDLE с валидным хитбоксом цели: «дальний» = первый вариант с
  наибольшим `m_HitBox.max.x` (кроме SWAP), его первый элемент ввода `m_eCancelInput` и `m_nDuration`;
  «быстрый» = первый с наименьшим `m_nHitBoxStart`; «особый» = первый, чей первый элемент содержит
  SPECIAL; «снаряд» = последний с `ProjectileSpeed > 0` и SPECIAL; «антиснаряд» = последний с неуязвимостью
  к снарядам. Жмётся только **первый** элемент ввода (у моушен-приёмов — «вниз», т. е. ничего; install не
  проверяется). `reach = max.x дальнего + max(0, max.x мировых хёрт-боксов соперника)` (так в коде — зависит от
  положения на сцене).
- Снаряд соперника летит на меня (`proj_d` — расстояние от его коробки до моих хёрт-боксов):
  - `proj_d < 600` (все уровни): 50 % антиснаряд (если есть), иначе `RandomInt(0,3)`: 0–1 — рывок вперёд
    (F 3 кадра, пауза 4, F 3), 2 — «назад» 3 кадра, 3 — обычная логика;
  - `proj_d ≥ 600`: MEDIUM/HARD с 50 % бросают свой снаряд (держат 10–20 кадров), иначе обычная логика.
- Обычная логика:
  - `dist ≥ reach + 300` — «вперёд» 20 кадров;
  - `dist ≤ reach` (в досягаемости):
    - MEDIUM/HARD: если у действия соперника есть хитбокс и мой быстрый разгон < `HitBoxStart_соп − кадр_соп` —
      с p = 0.5 / 0.7 быстрый приём, иначе 50 % дальний / 50 % ничего, держать `конец_действия_соп + 5`
      кадров; иначе если хитбокс соперника достаёт (`dist ≤ max.x хитбокса_соп + max.x хёрт-бокса моего IDLE`) —
      с p = 0.5 / 0.7 «назад» (блок), иначе ничего, держать `конец_действия_соп + 5`;
    - выбор атаки: p1 = 0.1, p2 = 0.1 (EASY) или 0.25, 0.66 (MEDIUM/HARD, без угрозы): с p1 — быстрый
      (держать `длительность + RandomInt(0,6)`), иначе с p2 — дальний (так же), иначе пауза `RandomInt(1,5)`.
      Итого EASY 10 % / 9 % / 81 %, MEDIUM/HARD 25 % / 49,5 % / 25,5 %;
  - между (`reach < dist < reach + 300`): MEDIUM 10 %, HARD 20 % — снаряд; ещё раз 10 % / 20 % — «особый»;
    иначе (и всегда у EASY) 75 % «вперёд», 25 % «назад» на `RandomInt(10,20)` кадров.
- EASY сознательно не блокирует (только случайный шаг назад) и не бросает снаряды в ответ.
- Доказательство: `FUN_182aacde0`:
  ```c
  if (me->action != 0) return 0;
  if (reach + 300.0 <= dist) { in = FWD; until = now + 20; }
  if (level < 1) { p1 = 0.1; p2 = 0.1; } else { ... p1 = 0.25; p2 = 0.66; }
  if (RandomFloat(0,1) < p1) { in = fastest; until = now + fastDur + RandomInt(0,6); }
  else if (RandomFloat(0,1) < p2) { in = farthest; ... } else until = now + RandomInt(1,5);
  ```
- Уверенность: высокая (дерево и числа); средняя — точный смысл `reach` (Valve складывает мировую координату).
- Сейчас в порте: своя модель (реакция 26/17/10, блок 0.18/0.5/0.82, наказания, комбо 0.35/0.7/0.95,
  `LEVEL`, 559–673).
- Что поменять: заменить `decide` на дерево выше (решение только в IDLE, удержание до кадра, без комбо;
  вероятности по уровням); при желании оставить исправленный `reach = max.x дальнего + ширина`, но пометить.

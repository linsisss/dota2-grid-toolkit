## 1. Кривая опыта

**Правило.** Опыт копится **суммарно** (не обнуляется на уровне). Герой стартует с уровня 1, опыт 0.
Переход с уровня L на L+1, когда `xpTotal ≥ floor(base · L^exp) · reqMult`, где base = `m_flRequiredExperienceBase` (5),
exp = `m_flRequiredExperienceExponent` (2.1), reqMult = 1 + Σ`m_flXPLevelUpRequirementMultiplier` эшелонов (в данных
везде 0 → 1). Кристалл: `xpTotal += xp · (1 + ExpMultiplier)`. За один подбор — максимум один уровень; после выбора
карточки проверка повторяется (так «долг» уровней раскрывается по одному).

Пороги (суммарный опыт для достижения уровня N = floor(5·(N−1)^2.1)): L2 = 5, L3 = 21, L4 = 50, L5 = 91, L10 = 504,
L20 = 2 422, L30 = 5 888, L40 = 10 969, L41 = 11 569.

**Тиры кристаллов** — только вид: `xp ≥ 20` → 3-й, `5 ≤ xp < 20` → 2-й, иначе 1-й (жёстко в коде 0x182d27520, значение
в контрольную точку частицы). Конвары `dota_survivors_exp_tier2_minimum/tier3_minimum` в коде нигде не читаются
(есть только регистрация).

**Доказательство.** 0x182d1a560 (требование), 0x182d16b60 (набор):
```c
return floorf(powf((float)level, def->m_flRequiredExperienceExponent) * def->m_flRequiredExperienceBase)
       * game->difficulty.xpLevelUpRequirementMult;            // game+0x374
...
player->xp += (GetAttr(ExpMultiplier) + 1.0) * amount;        // player+0x184, накопительно
if (XPRequired(game, player->level) <= player->xp) { player->level++; QueueReward(player, 2); }
```
Старт: ctor героя (CSurvivorsPlayer) 0x182d070e0 `param_1[0x30] = 1` (level=1, xp=0).

**Уверенность:** высокая.

**Сейчас в порте:** `xpTotal/xpToNext` (logic.mjs:294–295) — та же формула, но опыт хранится «до следующего уровня»
(`p.xp -= xpToNext`), шаги округлены по отдельности (`round(a_L − a_{L−1})`), `reqMult` нет.

**Что поменять:** хранить суммарный опыт и сравнивать с `Math.floor(5 * L ** 2.1) * reqMult`; полоску опыта считать как
`(xp − req(L−1)) / (req(L) − req(L−1))`. Разница с текущим — несколько единиц на высоких уровнях, но формула станет точной.

## 2. Счёт

**Правило.** Счёт копится по событиям: `score += points × E`, где **E = номер эшелона (1…8)** (`difficultyIndex + 1`).
Ни опыта как суммы, ни уровня, ни времени в формуле нет.

| Событие | Очки ×E | Где |
|---|---|---|
| убит обычный враг (в т. ч. ящик, ваза) | 10 | OnDeath, тип 1 / 9 |
| подобран кристалл опыта (любого размера) | 10 | сбор, тип 5 |
| убит элитный юнит (`m_bIsElite`: каждый лучник Гвардии пепла, каждый гранитный голем любого размера, Поглотитель, Неугасающая душа, башня) | 100 | тип 3 |
| убит Кроха Рошан (enemy 1505, носитель сундука) | 100 | тип 2 |
| подобран сундук (pickup 8/10) | 100 (+100 ещё раз со скипетром Метки) | в Simulate |
| подобран Скипетр Аганима (pickup 5) | 500 | в Simulate |
| осколок (pickup 4) | 0 | — |
| переход в тронный зал (конец первого этажа) | 10 000 | EnterBossStage, тип 12 |
| убита Империя (`IsBoss`) | 50 000 | тип 14 |
| `m_bIsMiniboss` (в данных ни у кого нет) | 2 000 | тип 4 |

Очки за убийство даются только если у врага `m_bSpawnPickupsOnDeath` (снимается при исчезновении вдали и при
«умирает при касании»): исчезнувшие и самоубившиеся о героя пауки очков и опыта не дают.

**Доказательство.** 0x182d1c190:
```c
case 1: case 5: case 8: case 9:  score += (diffIdx + 1) * 10;    return;
case 2: case 3: case 6: case 0xb: score += (diffIdx + 1) * 100;  return;
case 4:  score += (diffIdx + 1) * 2000;  case 7: ... * 500;  case 10: ... * 1000;
case 0xc: score += (diffIdx + 1) * 10000;  case 0xe: iVar1 = 50000; // Империя
```
Тип по врагу (OnDeath 0x182ce59b0): `IsBoss()→14; id==0x5e1→2; m_bIsMiniboss→4; m_bIsElite→3; id==1000→9; иначе 1`.
Сундук/скипетр — 0x182d27f80: `if (((id-8)&~2)==0) score += (diffIdx+1)*100; … else if (id==5) score += diffIdx*500+500;`.

**Уверенность:** высокая.

**Сейчас в порте:** `SCORE` (logic.mjs:31) и `computeScore` (1466): 40·опыт + 100·уровень + 5·секунда + 2500·мини-босс +
25 000 за победу, ×(1 + 0,25·(эшелон−1)) — целиком наше.

**Что поменять:** завести `game.score` и начислять по таблице выше в `killEnemy` (обычный/ваза 10, `def.elite` 100,
`baby_roshan_item_holder` 100, Империя 50 000), в `collect` (кристалл 10, сундук 100 и ещё 100 со скипетром Метки,
скипетр 500), в `startBoss` (10 000); всё × номер эшелона. Удалить `SCORE.second/level/killXp/elite/echelon`.
Если врага убивает касание (паук) или он исчез — не начислять.

## 3. Урон касанием

**Правило.** Каждый враг сам по себе: касание наносит `touch = m_flTouchDamage × (1 + Σ EnemyDamageMultiplier)`
(множитель вшивается при спавне) и ставит **этому врагу** перезарядку **0,25 с**. Общей неуязвимости героя после
удара **нет** (эффект «player_hit» 0,4 с — только частица, флаг модификатора 0x800, а неуязвимость = флаг 2).
Урон по герою: `dmg × (1 − Armor)` (без ограничения 0,9). Если `m_bDieOnTouch` — враг умирает без дропа и очков.
Если у эшелона `m_flEnemyTouchMovementSlowDuration > 0` — после удара модификатор замедления на это время.
Отражение (Blade Mail): `DamageReflection × исходный урон` (до брони) атакующему.
Неуязвим герой только при модификаторах с флагом 2: `stampede_invulnerable`, `game_won_invulnerable`
(и `m_bInvulnerable`). Модификатора неуязвимости на рывке не найдено (см. «Не проверено»).
При HP < 25 % — реплика `low_health` (в порте 30 %).

**Доказательство.** ctor врага 0x182cae3b0: `param_1[0x59] = 0x3e800000; … +0x2c4 = diffDamage * def->m_flTouchDamage;`
касание 0x182ce6c90:
```c
if ((flags & 2) && !dying && touchTimer(+0x2cc) <= 0.0) {
  dealt = player->TakeDamage(TouchDamage(), ...);
  if (dealt > 0) { if (game->diff.touchSlow > 0) AddModifier(player, 8 /*slow*/, touchSlow);
                   touchTimer = 0.25; }
  if (m_bDieOnTouch) { hp = 0; m_bSpawnPickupsOnDeath = 0; } }
```
урон по герою 0x182d21270: `fVar13 = (1.0 - GetAttr(16 /*Armor*/)) * amount; … modifier flags 0x800, dur 0.4`.

**Уверенность:** высокая по числам; средняя по частоте — 0,25 с верно, если физика присылает событие контакта каждый
тик, пока тела соприкасаются (вызов из обработчика контактов 0x182d1bce0).

**Сейчас в порте:** `TOUCH_COOLDOWN = 1`, `HIT_GRACE = 0.2` (logic.mjs:22–23), `hurtPlayer` (600): общий щит 0,2 с,
рывок даёт неуязвимость, броня ограничена 0,9, множитель эшелона применяется в момент удара.

**Что поменять:** `TOUCH_COOLDOWN = 0.25`, убрать `HIT_GRACE` и `p.invulnerable` после удара; броню не ограничивать
(или ограничить 1); отражение считать от урона до брони; порог реплики 0,25. Неуязвимость на рывке — оставить как
есть до проверки (см. ниже).

## 4. Империя (CSurvivorsImperiaBoss)

### 4.1 Порядок атак

**Правило.** Две независимые очереди.

1. **Цикл** (жёстко в ctor): `[3 снаряды, 4 с] → [2 порталы, 4 с] → [0 метеоры, 4 с] → …` по кругу. Первая атака —
снаряды через 4 с после появления. В момент применения атаки сразу ставится следующая с задержкой 4 с (таймер идёт
во время анимации; стоит только при оглушении или полной заморозке).
2. **Ярость**: таймер с `m_flInitialEnrageTime` (30), затем `m_flIncrementalEnrageTime` (30). Каждая ярость —
атака из списка ярости `[1 лучи]` (т. е. **лучи только на ярости**), и `enrage += (enrage < 4 ? 1 : 4)` (0→1→2→3→4→8→12…),
звук `survivors.imperia.enrage`. Лучи затирают стоящую в очереди атаку цикла — она пропускается; после лучей идёт
следующая атака цикла с её задержкой 4 с.
3. **Пороги здоровья** (`m_vecMandatoryEnrageHealthThresholds` [0.66, 0.33], у «Стойкости вождей» — [0.75, 0.5, 0.25]):
когда HP падает до порога **и** `enrage < исходное число порогов`, HP **обрезается ровно до порога** (лишний урон
сгорает), таймер ярости дозаполняется → ярость (лучи) на следующем тике, порог снимается. Если ярость по времени уже
догнала число порогов — пороги больше не срабатывают.

Числа по уровню ярости: снарядов `3 + 2·enrage`, скорость `700 + 40·enrage`; метеоров `3·(enrage+1)`; при `enrage > 3`
— «амбиентные» частицы тела/крыльев.

**Доказательство.** ctor 0x182d05d50: `seq.push(0x4080000000000003); seq.push(0x4080000000000002);
seq.push(0x4080000000000000); enrageList.push(1); … this->pending = seq[0].id; this->delay = seq[0].delay /*4.0*/`.
Simulate 0x182d29390:
```c
if (enrageTimeLimit <= enrageAcc) {
  Schedule(this, enrageList[enrage % n], 0);
  enrage += (enrage < 4) ? 1 : 4;   // cmovl ecx, r15d(=1), иначе 4
  enrageTimeLimit = m_flIncrementalEnrageTime; enrageAcc = 0; }
if (delay <= 0 && pending != -1) { id = pending; pending = -1; ExecuteAttack(id); } // 0 метеоры,1 лучи,2 порталы,3 снаряды
```
Порог 0x182d211d0: `if (n>0 && hp <= th[0]*maxHp && enrage < thCount0) { enrageAcc = enrageTimeLimit; hp = th[0]*maxHp; pop(th); }`.

**Уверенность:** высокая.

**Сейчас в порте:** `BOSS_ORDER = [missiles, meteors, portals, missiles, rays]` (logic.mjs:1361) с паузами 2,5/3,5/2/1,2 с;
ярость +1 без ограничений и по порогам без условия `enrage < n`, без обрезки HP; лучи в общем цикле.

**Что поменять:** цикл `['missiles','portals','meteors']`, первая атака через 4 с, следующая — через 4 с после начала
предыдущей; лучи — только при ярости (каждые 30 с и на порогах); `enrage += enrage < 4 ? 1 : 4`; порог: срабатывает,
только если `enrage < исходная длина порогов`, HP ставится ровно в порог; ярость по порогу = досрочный запуск
таймера ярости (таймер после неё снова 30 с).

### 4.2 Магические снаряды (атака 3)

**Правило.** `n = 3 + 2·enrage` снарядов веером на героя, шаг `min(15°, 100°/3) = 15°`, симметрично. Вылет из точки
босс + 100·dir, через **0,7 с** после каста, летят **по прямой** (самонаведения в `CSurvivorsProjectile` нет — только
отсчёт жизни), скорость `700 + 40·enrage`, жизнь 4 с, радиус 50, урон 15.

**Доказательство.** 0x182d13830: `n = m_nNumMagicMissiles + enrage*2; step = min(15, 100/m_nNumMagicMissiles);
… start = pos + dir*100; end = pos + dir*speed*5; life = 4.0; delay = 0.7; speed = base + enrage*inc`.
Жизнь снаряда 0x182d98960 — только `life -= dt`.

**Уверенность:** высокая (по прямой — средняя-высокая).

**Сейчас в порте:** 3 снаряда всегда, разлёт 0,5 рад, `homingPlayer: true, turn: 1.6`, жизнь 6 с (logic.mjs:1376–1382).

**Что поменять:** n = 3 + 2·enrage, шаг 15°, без наведения, задержка вылета 0,7 с, жизнь 4 с.

### 4.3 Метеоры (атака 0)

**Правило.** `n = 3·(enrage+1)`. Точки: №0 — под героем; №1–2 — на случайном угле на 2R; №3–5 — на 4R; №6–8 — на 6R;
№9+ — `x += cos(a)·U(0,2500), y += sin(a)·U(0,2500)` (R = `m_flBurningGroundImpactRadius` = 280); точки
прижимаются к проходимой сетке. Падение через `SpawnDelay + 0,15·i` (2 + 0,15·i). Огонь `FlamesDuration` 5 с: пока герой
в радиусе R — модификатор горения на `DoTDuration` 3 с, тик 0,5 с по `DoTDamage·0,5` (= 4/с).

**Доказательство.** 0x182d12300: `count = (enrage+1) * m_nBurningGroundInstancesPerEnrageLevel; if(i==0) pos=hero;

**Уверенность:** высокая.

**Сейчас в порте:** первая под героем, остальные 150…850 от героя + упреждение по скорости (logic.mjs:1385–1390).

**Что поменять:** кольца 560/1120/1680 по три, дальше — случайно до 2500 по осям; без упреждения.

### 4.4 Демонические порталы (атака 2) — закрытие

**Сейчас в порте:** закрытие после 5 с стояния рядом (`q.standing >= 15/3`, logic.mjs:1446–1450), точка случайная,

## 5. Сундук и карточки

### 5.1 Что даёт сундук

**Правило.** Награды встают в очередь героя (CSurvivorsPlayer): 2 — уровень, 4 — сундук, 6 — осколок, 7 — скипетр. Каждая (не только
уровень) запускает волну отталкивания и задержку `m_flLevelUpDelay` (0,5 с) перед окном выбора. **Сундук (pickup 8/10)
= выбор 1 из 3 предметов** (только `m_bIsPassive`), со скипетром Метки — второй такой выбор. Скипетр — до 3 из своих
способностей с `m_bIsScepterUpgradeable` без скипетра, перемешано.

Генерация предметов (0x182d16da0):
- кандидаты: пассивные `m_bRollable`, не в «чёрном списке» героя (+0x2c8: компоненты собранных комбинаций);
  своё и не на максимуме → «своё»; нового нет и рецепта нет → «новое», только если занято < `m_nMaxPassiveSlots` (6);
  с рецептом → «комбинация», если все компоненты есть и на максимуме (слоты не нужны);
- **комбинации идут первыми**, все (перемешанные), до 3;
- затем слот «новое» добавляется с вероятностью **1 − 0,6 = 0,4** (`r ≥ m_flPassiveItemGenerationWeight`), слот «своё» —
  с вероятностью **1 − 0,35 = 0,65** (`r ≥ m_flExistingItemGenerationWeight`), остальное — «любое»
  (общий пул новое+своё); каждый слот берёт случайный элемент своего списка, не повторяясь; пустые добираются из
  общего пула; ничего — «Мешочек с золотом» (id 999); в конце перемешать.

**Доказательство.** очередь/задержка 0x182d2a490 и 0x182d0c830 (`if (reason==2) "levelup"; 4 "acquire_item"; 6 shard;
7 scepter; … levelup_knockback …; delay = m_flLevelUpDelay`). Сундук в 0x182d27f80: `if (((id-8)&~2)==0) { … queue.push(4);
if (GetActive(21 /*track*/)->scepter) queue.push(4); }`. Полярность сравнения проверена по ассемблеру:
```asm
182d17291: comiss xmm0(r), [rsi+0x1d8]   ; jb skip  -> push 4 ("новое") если r >= 0.6
182d172f1: comiss xmm0(r), [rsi+0x1d0]   ; jb skip  -> push 3 ("своё")  если r >= 0.35
```

**Уверенность:** высокая.

**Сейчас в порте:** сундук — одна карточка из общего пула уровня (`levelUpChoices(game, 1)`, logic.mjs:1227–1231);
волна отталкивания только на уровне (1211, ×4 к дистанции).

**Что поменять:** сундук → окно из 3 предметов по правилу выше (комбинации первыми); волна и 0,5 с — на любой награде;
дистанция отталкивания — `m_flLevelUpKnockbackDistance` (60) без ×4 (длительность — `m_flKnockbackDuration`, в данных
нет → значение по умолчанию схемы).

### 5.2 Карточки уровня

**Правило.** **Уровень даёт только способности** (`!m_bIsPassive && !m_bIsInnate && m_bRollable`); предметы —
только из сундуков.
- слоты: `m_nMaxActiveSlots (5) + ActiveAbilitySlots`;
- «своё» — есть и `level < m_nMaxLevel`; «новое» — нет и слоты не заняты;
- maxed-способности предлагаются, только если `LimitBreak > 0` **и** все слоты заняты **и** всё на максимуме (атрибут
  LimitBreak в данных не выдаётся ничем → на практике никогда);
- слот «своё» с вероятностью **0,35** (`r ≤ 0,35`), слот «новое» — **0,7** (`r ≤ 0,7`), остальное до
  `m_nLevelUpChoices` (3) — «любое»; выбор и добор как у предметов; пусто → id 999; перемешать;
- строка улучшения: уровень L (1…) → `m_vecAuthoredUpgradeChoices[L−1]`; если L > числа авторских строк — случайная
  `m_vecMinorUpgradeChoices`.
- Замена (reroll) — для уровня, сундука и скипетра; текущие карточки исключаются (если есть другие).
- После выбора (если время ≥ 1 с) оставшаяся перезарядка выбранной способности = `min(1,5, 0,7·КД)`
  (`dota_survivors_max_remaining_cooldown_after_upgrade`).

**Доказательство.** 0x182d18130 (ассемблер):
```asm
182d1852b: movss xmm1,[r14+0x1d0]; comiss xmm1,xmm0(r); jb skip -> push 1 ("своё") если 0.35 >= r
182d18580: movss xmm1,[r14+0x1d4]; comiss xmm1,xmm0(r); jb skip -> push 2 ("новое") если 0.7 >= r
```
фильтр: `def[0x70]==0 && def[0x71]==0 && def[0x73]!=0 && (level < maxLevel || limitBreakAllMaxed)`.
КД: 0x182d1fcb0 `SetCooldown(min(convar 1.5, GetCooldown()*0.7))`. Замена: popups 0x18292… (вызов с массивом текущих id).

**Уверенность:** высокая (КД после выбора — средняя: не проверено, «ставит» ли или «не больше»).

**Сейчас в порте:** `levelUpChoices` (logic.mjs:219) — взвешенная выборка без возврата по всем видам: своё 0,35, новое 0,7,
предметы ×0,6, комбинации вес 100, maxed → «Усилить» с весом 0,175; замена только на уровне; КД → `min(КД, 0,1)` (199).

**Что поменять:** разделить генераторы: уровень — только способности (алгоритм «слоты 1/2/5» выше), сундук — только
предметы; убрать «Усилить» для maxed (или оставить только под LimitBreak); замена для всех трёх окон с исключением
текущих; КД после выбора `min(1.5, 0.7·cooldown)`.

## 6. Разделение врагов

**Правило.** Слои 1 SMALL (230), 2 LARGE (320), 3 ELITE (360); OFF не участвует. Враг слоя k отталкивается от врагов
своего и **всех более крупных** слоёв (k…3), мелкие крупных не толкают. Порог пары `(d_own + d_other)/2`. Вклад соседа
на расстоянии d < порога: `(my − other)/d · (1 − d/порог)` (линейно); совпали (d² < 1e-4) — случайный единичный.
Сумма **нормируется в единичный вектор** → `m_vSeparationVector`. Каждый тик:
`sepVel += (Influence·sepVec − sepVel) · clamp(dt·InterpSpeed, 0, 1)` (0,55 и 25), направление движения
`normalize(facing + sepVel)`, скорость — полная скорость врага (разделение только поворачивает, не тормозит и
не разворачивает: |sepVel| ≤ 0,55 < 1). Считается каждый тик для всех, параллельно.

Рядом в том же Simulate: поворот к цели — `m_flTurnRate` **в градусах/с** × (1 + Σ EnemyTurnRateMultiplier)
(конвар-оверрайд), без поправок; без turn rate — мгновенно. Пока герой мёртв/воскресает — враги идут **от** него со
скоростью ×1,5. Стрелки стоят, если герой ближе минимальной дальности их атак.

**Доказательство.** 0x182d0aec0:
```c
th = (dist[ownLayer] + dist[layer]) * 0.5;            // layer = own..3
if (d2 < th*th) { if (d2 > 0.0001) { d = sqrt(d2); v += (delta/d) * (1.0 - d/th); } else v += RandomUnit(); }
...
enemy->m_vSeparationVector = Normalize(v);
```
0x182cf7cc0: `sepVel += (m_flSeperationVelocityInfluence*sepVec - sepVel) * clamp(dt*m_flSeperationVelocityInterpolationSpeed,0,1);
dir = Normalize(facing + sepVel); vel = dir * MoveSpeed() * (heroDown ? 1.5 : 1.0);`
угол — `AngleDiff` 0x183842ae0 (градусы, ±180).

**Уверенность:** высокая (числовые значения enum слоёв SMALL/LARGE/ELITE = 1/2/3 выведены из кода: в цикле ключи 1…3).

**Сейчас в порте:** logic.mjs:1095–1110 — дистанции ×0,42, квадратичный вес, только «свой размер или больше» по
максимуму, вектор не нормирован, смешение `dx·(1 − 0,55·|s|) + s·0,55` меняет скорость; поворот
`turnRate·π/180·6` и мгновенно ближе 200 (1083); при смерти героя `dx *= −0.3` (1088).

**Что поменять:** перенести формулу выше 1:1 (дистанции vdata без ×0,42, линейный вес, нормировка, слои k…3,
`normalize(facing + sepVel) · speed`); turn rate в °/с без ×6 и без «200»; при мёртвом герое — от героя ×1,5.

## 7. Разброс урона

**Правило.** В `CSurvivorsPowerUp::ApplyDamage` физическая и магическая части независимо умножаются на
`U(1 − p, 1 + p)`, p = `dota_survivors_actual_random_damage_range_percent` = 0,1, **до** бонусов. Далее: снаряд →
маг. += `Projectile_BonusMagicDamage`; физ. > 0 → физ. += `BonusPhysicalDamage`, ×(1 + physical_weakness), метка Кеза
(«vulnerable»: множитель `VulnerabilityDamagePercent`, оглушение, метка снимается) и крит (`шанс`, +`Crit_Phys_DamageMultiplier`)
**складываются** в один множитель; крит снаряда (шанс/множитель 61/62) — × обе части. Итог одной суммой в TakeDamage.

**Доказательство.** 0x182d0e940:
```c
r = convar(actual_random_damage_range_percent);
phys  *= RandomFloat(1.0 - r, r + 1.0);
magic *= RandomFloat(1.0 - r, r + 1.0);
if (isProjectile) magic += GetAttr(63);
if (phys > 0) { phys += GetAttr(66); … mult = vuln.percent; if (rand < critChance) mult += GetAttr(11); if (mult > 0) phys *= mult; }
```

**Уверенность:** высокая.

**Сейчас в порте:** `hitEnemy` (logic.mjs:472) — без разброса; метка ×(1 + vuln), крит отдельно (не складываются).

**Что поменять:** в `hitEnemy` до всех бонусов `dmg *= 0.9 + 0.2·random()` (раздельно для физ./маг., если удар
смешанный); метку и физ. крит складывать в один множитель `vuln + critMult`.

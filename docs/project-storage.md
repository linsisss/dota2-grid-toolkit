# Сохранение и восстановление проекта

`scripts/project-storage.mjs` отвечает за сохранность документа. `App.jsx` читает хранилище **до** открытия редактируемого холста; `app.mjs` передаёт изменения и показывает статус.

## Совместимость обновлений

README и страница перехода GitHub Pages не меняют формат проектов или хранилище редактора. Страница перехода не читает и не очищает данные браузера, не переносит их между origin. Перед заменой старого редактора на Pages нужно учитывать, что локальные проекты старого адреса не появятся автоматически на gridstudio.me; перенос выполняется экспортом и импортом JSON. Исходный редактор и лендинг собственного домена остаются отдельными точками входа.
Сдвиг незавершённой фигуры с Shift хранится только в текущем жесте. До отпускания мыши исходный документ не меняется; при завершении записываются обычные символы, одним шагом истории. Формат проектов, экспорт и схема хранения прежние. Рисунок из отдельного окна по-прежнему попадает в основной проект только по кнопке добавления.

Исправление обновления лайков и унификация размеров вкладок каталога не меняют аккаунты, публикации или сохранения проектов. Ответ лайка применяется к карточке в памяти страницы; серверная схема и ключи браузера прежние.

Анимации спойлеров и интерфейса — временное состояние DOM, включая рассчитанную по высоте длительность раскрытия. Они не меняют документ, историю отмены, сохранения или навигацию между файлами. `useAppMotion` снимает обработчики и завершает активные анимации при размонтировании.

Поле Steam-профиля и папка установки из инструкции экспорта хранятся только в памяти страницы. Они не попадают в документы, резервные копии, Dota JSON, каталог или Telegram. Ключи/схема сохранений не меняются.

Изменение оформления карточек Telegram не меняет схему `telegram_reviews`, ревизии каталога или документы редактора. В базе остаются прежние summary/actor/outcome; новые подписи собираются при отправке и обновлении сообщения, миграция данных не нужна.

Действие лендинга `/editor?new=1` создаёт новый workspace, не затрагивая существующие. После успешного сохранения документа запоминается его ID в сессии вкладки, параметр `new` удаляется через `replaceState`. Перезагрузка продолжает этот файл; ошибка создания сохраняет прежнюю навигацию. Формат документов, журнал и ключи хранения не меняются.

Каталог хранится отдельно на сервере. Его секретные ссылки сохраняются под новым ключом `gridstudio.catalog.ownership.v1`; ключи и схема автосохранения редактора не менялись. Открытие сетки из каталога сначала показывает подтверждение, затем добавляет её к текущему документу одной отменяемой операцией. Публикация извлекает только активную видимую сетку и не меняет исходный документ, его слои или остальные сетки.

- Неизменный ключ: `dota-grid-studio.document.v1`. Данные остаются native-проектом schema 1; старый ключ и импорт сохранены.
- IndexedDB: `gridstudio-projects`, store `documents`, версия базы 1. Версии приложения не должны переименовывать БД/ключ.
- Native JSON дополнен служебным `_studioSave` (ID записи, версия, время, авторская вкладка, родитель, признак конфликтующей копии). При загрузке в редактор поле удаляется из рабочего документа; на игровой Dota JSON оно не влияет.
- До миграции/первого сохранения в новой версии исходная строка сохраняется целиком, включая неизвестные поля. Если нет места для защитной копии, старое основное сохранение не перезаписывается.
- Если все копии не читаются, открывается пустое рабочее поле с явной ошибкой и защитой оригинала. Исходные данные доступны для скачивания; демопроект не записывается поверх них.

## Запись

Пауза после ввода 250 мс, максимальное ожидание при непрерывной работе 1 секунда. На visibilitychange, pagehide и размонтировании запись сбрасывается немедленно. Перед асинхронной транзакцией создаётся синхронный журнал отдельной вкладки в localStorage. При недостатке места/закрытии до завершения записи показывается стандартное предупреждение браузера о несохранённых изменениях.

IndexedDB хранит актуальную копию и до 10 автокопий по минутным слотам; копии перед обновлениями/восстановлениями не попадают под эту ротацию. localStorage хранит зеркало для совместимости и журнал последнего ввода. Если IndexedDB недоступна, localStorage сохраняет предыдущую хорошую запись перед заменой. Если localStorage заполнена, работа сохраняется в IndexedDB. При отказе обоих хранилищ статус не утверждает, что проект сохранён, и предлагает скачать файл.

Записи сериализованы. Web Locks координируют обычные записи между вкладками, а IndexedDB дополнительно сравнивает ожидаемую предыдущую запись в одной атомарной транзакции. Проверяется и актуальная строка localStorage. Вкладка с конфликтом не перезаписывает общий документ: сохраняет свою отдельную копию, сообщает об этом и позволяет восстановить её вручную. Незавершённый журнал восстанавливается автоматически только если он относится к актуальной ветке; чужая конфликтная копия не должна самовольно становиться основным проектом.

Меню «Версии проекта» открывается по единой кнопке «Изменения сохранены» в шапке или из справки. На телефоне это компактная кнопка с цветной точкой статуса. Статус через scripts/save-status.mjs учитывает локальную запись и синхронизацию аккаунта: пока запись не завершена, показывает «Сохраняем…», при ошибке — предупреждение вместо успеха. Локальная ошибка имеет приоритет даже после успешного ответа сервера. Две отдельные подписи устройства/аккаунта убраны; механика автосохранения не менялась. Меню показывает время, имя, причину и версию, позволяет скачать исходный JSON, в том числе нераспознанный. Восстановление сначала архивирует текущий документ и актуальные сохранения других вкладок, затем заменяет рабочий документ одной отменяемой операцией.

## Что сохраняется

Место в интерфейсе хранится отдельно, в `sessionStorage` под ключом `gridstudio.workspace-session.v1`: только ID файла и индекс выбранной сетки. Обновление вкладки восстанавливает редактор после чтения реестра и завершения проверки аккаунта. Переход «Файлы» очищает эту запись; отсутствующий, архивный или чужой файл автоматически не открывается. Заблокированный sessionStorage отключает только восстановление навигации. Вкладки не перезаписывают место друг друга; ключи документов, автосохранение и резервные копии не меняются.

Весь native-документ: активная сетка, исходный файл со всеми сетками, отредактированные configDrafts, слои, скрытые объекты, координаты, герои, размеры холста, подложка. История Ctrl+Z существует в памяти сеанса, не восстанавливается после перезагрузки. Настройки/картинка ещё не подтверждённого окна конвертера и не добавленный на холст черновик рисования не являются частью native-документа.

Хранилище привязано к origin: https://gridstudio.me и его /editor используют один origin; www, HTTP, другой домен/порт — отдельное хранилище. Обновления должны сохранять HTTPS-домен и не отправлять Clear-Site-Data, не выполнять localStorage.clear/deleteDatabase и не принудительно перезагружать открытый редактор. Старый bundle должен продолжать работать до обычного обновления вкладки. При переходе на другой домен проект надо перенести скачанным файлом.

Без аккаунта восстановить данные после очистки браузера, потери профиля/диска или удаления данных в инкогнито невозможно. Гостевые файлы не имеют искусственного срока удаления. Для независимой копии — «Скачать текущий проект», не только Dota JSON. Файлы, явно сохранённые в Telegram-аккаунт, дополнительно синхронизируются с сервером; после входа можно получить их на другом устройстве.

## Несколько рабочих пространств

Превью в списке файлов (`scripts/workspace-preview.mjs`, `src/WorkspacePreview.jsx`) читает текущую сетку, configDrafts и нетронутые сетки исходного файла. Перелистывание не записывает документ и не переключает сохранённую активную сетку. При открытии выбранный индекс передаётся редактору отдельно и применяется через switchConfig, сохраняя остальные сетки и черновики. При недоступности сервера используется локальная копия; несинхронизированные локальные правки имеют приоритет.

`/editor` открывает список файлов (`src/Workspaces.jsx`), один файл может содержать несколько сеток. Старый проект становится элементом `legacy` и продолжает использовать исходные ключи без перемещения данных. Новые файлы имеют UUID: localStorage получает суффикс `.workspace.UUID`, IndexedDB — префикс `workspace:UUID:`. База остаётся версии 1. Резервные копии, журналы и блокировки разделены по файлам. Реестр хранится в `registry:` и зеркалируется под `gridstudio.workspace.info.UUID`; повреждённый старый проект сохраняется как доступный для восстановления файл.

`scripts/workspaces.mjs` сохраняет правки локально до синхронизации. Серверная запись отложена на 1,5 секунды (не более 5 секунд при непрерывной работе), отправки последовательны. Сервер сравнивает ревизии; при конфликте чужая версия не заменяет локальную. Нужно создать копию из списка файлов. Серверная версия перед загрузкой также защищает прежнюю локальную копию через механизм восстановления. Ошибки сети не сбрасывают dirty-флаг и не стирают документ. После возвращения связи можно повторно открыть файл для синхронизации.

По актуальному решению пользователя вход автоматически привязывает гостевые файлы к аккаунту, без дублирования карточек. Локальные документы и копии остаются по прежним ключам; у legacy отдельный cloudId UUID. pendingUpload сохраняет незавершённую отправку для повторения после сетевой ошибки. Файлы другого аккаунта не переносятся. Новые и импортированные файлы после входа также сохраняются в аккаунт автоматически. Архивирование обратимо. Полный native-документ, включая подложку и все сетки, сохраняется в аккаунте; публичная публикация по-прежнему содержит только выбранную сетку. Детали прав, cookie и лимитов — [accounts-workspaces.md](accounts-workspaces.md).

## Проверки

Перестановка героев записывает только новый порядок `heroIds` при отпускании внутри группы. Координаты анимации не входят в документ, автосохранение и экспорт. Один перенос — одна запись undo; Esc, отмена pointer-жеста и отпускание вне группы не создают изменений. Формат хранилища и Dota JSON не меняется (`hero_ids` уже хранит порядок).

Квота каталога (3 отправки гостю / 10 аккаунту за 24 часа) не меняет автосохранение и не удаляет проекты. Аккаунтная квота использует существующие записи `audit`/`works` в SQLite, включая удалённые публикации; при обновлении их нельзя очищать. Добавляются только индексы, без изменения формата пользовательских файлов.

`tests/project-storage.test.cjs` использует настоящую семантику IndexedDB-транзакций через fake-indexeddb. Проверяет старый файл, несколько сеток/подложку, резервирование до обновления, повреждённый JSON, восстановление журнала, quota/storage failures, одновременные записи, отдельную ветку второй вкладки, восстановление и ограничение автокопий. Проверять также reload + конфликт вкладок + восстановление через UI на локальном dev server. Production build для этой проверки не требуется.

### Telegram-модерация каталога

Карточки Telegram не затрагивают autosave редактора. PNG строится на сервере только из отправленной активной сетки; подложки, другие сетки проекта и секретные ссылки управления в чат не передаются. Решения и квитанции карточек сохраняются в SQLite (`telegram_reviews`, `telegram_runtime`), вместе с Telegram ID и именем проверившего; эти данные не входят в публичный API. Новая ревизия остаётся приватной до одобрения, старая публикация сохраняется.


Закрепление библиотеки хранится отдельно в `gridstudio.library-pinned` и не входит в документ/историю. Переименование любой сетки меняет только имя соответствующего source/draft/active состояния одной отменяемой операцией; переключения активной сетки и оптимизации арта при этом нет. Новый зелёный индикатор отражает успешное сохранение, промежуточное состояние — лавандовое, предупреждение — янтарное. Механизм автосохранения и версии хранилища не изменены.

### Проверка обновления 1.4.1 → 1.5 (29.09.2026)

- Браузер: настоящая сборка 1.4.1 и сборка 1.5 по очереди на одном origin и в одном профиле. Созданные в 1.4.1 файлы (герои, обычный, многострочный и повёрнутый текст с замерами 1.4.1, символы, ASCII-слой, заблокированный и скрытый слои, подложка, вторая сетка, импорт Dota JSON на 2907 категорий) и проект под старым ключом `dota-grid-studio.document.v1` открылись в 1.5 без единого отличия в документе (кроме `_studioSave`); у каждого появилась копия «Перед обновлением», зеркала localStorage совпали с IndexedDB, версия базы осталась 1. Устаревшие `textMetrics` (без `model`) 1.5 пересчитывает в памяти при отрисовке и экспорте и перезаписывает при следующем сохранении.
- Сервер: миграции 1.5 на снимке прод-базы (`VACUUM INTO`, 17 таблиц, 256 облачных файлов, 103 аккаунта, 120 работ) не изменили ни одной строки существующих таблиц; добавлены таблицы `arts`, `art_notices`, `author_notices`, `subscriptions`, `notifications` и столбец `audit.actor`. Сервер 1.4.1 открывает уже мигрированную базу — откат возможен. Снимок удалён после проверки.
